# wx-kit 文库素材创作编排

## Overview

把 wx-kit 的公众号文章变成创作素材，编排「取料 → 选题 → 写作」一条链，定稿后可选发到个人站点。**这是个薄编排层**：取料靠 wx-kit 的 CLI/导出文件，写作靠 `khazix-writer`（你的笔调在那儿），本 skill 只负责把素材拉过来、提选题、在两个关键点停下等你拍板。

**命令细节不在这里。** 参数、输出契约、安装与停用边界、错误码一律看 `wx-kit-skill`——本 skill 只说「哪一步该用什么」。

**核心原则:人在环中。** AI 收集素材、提选题候选、出初稿;**选题和定稿权在你**。两个检查点不可绕过——不要从素材一路冲到成品。

## When to Use

- 想拿文库里若干篇文章当素材，写一篇新稿。
- 用户已经给出一组文章 URL，希望下载后从中提炼选题。
- 已在文库 GUI 多选并「导出为素材」，手里有一个 `exports/*.json`。
- 想先从一批素材里看看「能提炼出哪些选题方向」再决定写哪个。

不适用：手上没任何素材、也不打算从公众号取（纯从零写直接用 khazix-writer）。

## 流程（两个检查点必停）

### 1. 取素材

> **参数、输出契约、环境差异一律以 `wx-kit-skill` 为准**（它随每次 CLI 变更同步）。
> 这里只说**在哪一步用哪个能力、为什么**——把命令细节抄进本文件正是它曾落后二十个版本的原因。

先看用户手上有什么，选一条路：

**A. 用户已提供文章 URL，但还没下载**

```sh
wx-kit download --url <URL1> --url <URL2> --formats md,meta
# 下载完成后再从文库按结果里的 id 导出
wx-kit library export --ids <id1>,<id2>
```

只下载用户明确提供的 URL。若用户只说“某公众号最近文章”或“昨天各号更新”，不要调用旧的
`search` / `crawl` / `subscription`：这些私有后台能力已经停用。应说明边界并请用户提供文章链接。

**B. GUI 已导出**：用户在文库多选 →「导出为素材」写出 `<库根>/exports/<时间戳>.json`。读最新那个。

**C. 库里现取**：

```sh
wx-kit library export --ids a,b,c        # 按文章 id
wx-kit library export --since 2026-07-27 # 按下载日期
wx-kit library export --account "某号"    # 按公众号（昵称包含匹配）
wx-kit library export --all              # 全库：没有选料器时必须显式给
wx-kit library search <关键词>            # 按标题找素材，再拿 id 去 export
wx-kit library list                      # 默认发布时间降序 → 取前 N 条即「最近 N 篇」
```

清单是 JSON：`{ ok, count, articles:[{ id,title,account,author,publishTime,sourceUrl,dir,contentPath }] }`。
**正文不在清单里**——按需读每篇的 `contentPath`（即 `dir/content.md`）拿全文。

如果用户没说选哪些，先问清楚（哪个号/哪几篇/哪个时间段），别自作主张导全库。

### 2. 读正文前先扫两个字段

这两个字段决定「这批素材能不能用、该怎么用」，**在选题之前看**：

- **`itemShowType`（消息类型）**：`0` 图文 / `5` 视频消息 / `8` 图片消息 / `10` 文字消息。
  **视频消息与文字消息没有长正文**——正文往往只是一段几十字的描述。
  拿它当素材时要清楚手里只有一句话，**别据此编出文章里并不存在的论据**。
- **`warnings`（解析告警）**：「下到了但可能不对」的唯一信号（遇到没适配的新消息类型、正文疑似脚本等）。
  正文读起来异常（超长乱码、明显不是文章）时**先看这个字段**，别把解析坏的东西当素材写进稿子。

### 3. 选题（轻量内联，借横纵交叉的思路）

读完选中文章的正文后，提炼 **3–5 个选题方向**，每个给：

- **角度**：一句话说清这篇要从什么切口写。
- **理由**：为什么这个角度成立/有意思（可借横纵思路——这批素材里的「时间线变化」或「彼此对照/张力」往往就是选题）。
- **HKR 自评**：Happy（有趣/有悬念）、Knowledge（有信息量）、Resonance（戳情绪）——标各项强弱，帮你快速判断。

> 这步是「从已有素材里提选题」，**不调 hv-analysis**（那是重量级单主题联网深研→出 PDF 的工具，错位）。若某个选题你想要联网深研支撑，见下方「旁路」。

### 🛑 检查点 1：你拍板选题

把候选列给用户，**停下等他选/改**。用户可能选一个、合并两个、或给新角度+结构。**在用户拍板前，绝不进入写作。**

### 4. 写作

把「选定的选题（角度 + 用户给的任何结构/要点）+ 选中文章正文」作为素材，**交给 `khazix-writer` skill 出初稿**（它自带 HKR 选题质检与卡兹克笔调；本 skill 不重复造写作能力）。

### 🛑 检查点 2：你审定

把初稿给用户，**停下等他审/改**。按反馈迭代，直到他满意。审阅/校验（事实核查、查重）是可选的后续，本 skill 不强求一版到位。

### 5.（可选）发到个人站点

定稿后**如果用户明确要求发布**，wx-kit 能直接按 Astro 站点规范落盘：

```sh
wx-kit site sync --ids <文章id> --slug <url-slug>     # 需先配好 siteSyncPostsDir
```

**默认不做。** 发布是不可逆的对外动作，和两个 🛑 是同一条原则：
用户没说「发」，就停在定稿。别因为「链路完整」把最后一步自动化掉。

## 旁路：需要联网深研时

若某个选题需要超出现有素材的事实/竞品/历史支撑，**单独**对该主题跑 `hv-analysis`（产出 PDF 研究报告），再把结论并入素材交给 khazix-writer。这是可选加深，不在默认流程里。

## 边界（勿越）

- 本 skill 只经 wx-kit 的 **CLI / 导出的 `exports/*.json`** 取数据，**绝不直接读 `library.json` 或 import wx-kit 代码**——换任何下载器/agent 都按同一契约接入。
- 不在本 skill 里重写选题/写作能力:选题轻量内联、写作全权交 khazix-writer。
- 素材用途:选题/研究/启发 + 人工主导创作;**不洗稿、不自动转发**。

## Common Mistakes

- **跳过检查点直接出成品**：最常见的错。两个 🛑 必须停。
- **未经要求就 `site sync`**：发布是对外且不可逆的，用户没说「发」就停在定稿。
- **自作主张 `--all` 导全库**：用户没指定就先问，别一股脑全导。
- **为了找某公众号文章而调用旧私有命令**：`search` / `crawl` / `subscription` 已停用；请用户给 URL。
- **下载后自己猜正文路径**：从下载结果取 id，再用 `library export` 获取可靠的 `contentPath`。
- **没看 `itemShowType` 就把视频/文字消息当长文用**：那类「正文」只有一段描述，据此写论据等于编造。
- **把清单里的 `contentPath` 当正文**：那是路径，要去读文件。
- **为选题去跑 hv-analysis**：错位且慢；选题轻量内联即可。
- **把 CLI 参数细节抄进本文件**：抄来的不会跟着源头变——本 skill 曾因此落后二十个版本。查 `wx-kit-skill`。
