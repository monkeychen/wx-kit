# M43 实现计划 — `digest --download`:一条命令给出可直接用的素材清单(v0.8.5 R1)

> 对应 `docs/PRD-v0.8.5.md` R1。分支 `feat/m43`。

## 已核实的事实(2026-07-28)

- **判重命中时已经带出库里的 `dir`**(`download-article.ts:48`),所以「已下载的也要有路径」不必新做。
- `library export` 的 `contentPath` 是**无条件** `join(dir, 'content.md')`(`material-export.ts:67`)
  ——若下载时没选 `md`,那个路径指向的文件其实不存在。**本次不照搬这个latent bug**:
  只在 formats 含 `md` 时给 `contentPath`(见下方决策 3)。
- `ArticleMeta` 自 M40 起有 `warnings`,所以**已在库的文章也能给出告警**,不必读 meta 文件。
- 现有 `DigestDeps.isDownloaded(id, url)` 只回 boolean —— 要带路径,这个注入点得换形状。

## 设计决策

1. **只读与下载切成两个 core 函数**,而不是给 `subscriptionDigest` 加一个 `download` 开关:
   `subscriptionDigest()` 仍然纯查询,`fetchMissing()` 单独一步。
   **这样「不带 `--download` 时行为一字不变」由结构保证,而不是靠一个 if 分支的自觉。**
2. **`isDownloaded` → `localOf`**:返回 `{ dir, contentPath?, warnings? } | null`。
   一次调用同时回答「有没有」和「在哪、有没有告警」——本来就是同一次查库。
3. **`contentPath` 只在正文文件真会存在时给**(formats 含 `md`)。
   给一个指向不存在文件的路径,比不给更糟:agent 会照着读然后失败,还得回头猜为什么。
4. **下载串行**,复用 `DownloadQueue`(它已有串行 + 随机延迟 + 频控退避),不自己写循环。
5. **失败留痕**:失败的条目留在清单里,`downloaded: false` + `error`,与 M40 的结论一致。
6. **`--no-video` 透传**:批量取素材时视频常常不需要,而单个可达上百 MB。

## 步骤(bite-sized,TDD,每步跑 `npm test`)

### A · core:`localOf` 换形状(`src/core/subscription-digest.ts`)

- **A1(红)** 改 `tests/core/subscription-digest.test.ts`:
  - `localOf` 返回 null → `downloaded: false`,**不带** `dir`/`contentPath`。
  - 返回 `{ dir, contentPath }` → `downloaded: true` 且路径带出。
  - 返回的 `warnings` 带进清单条目(已在库的文章也能给告警)。
  - 老库的哈希 id 靠 url 认出来那条用例保留(改成新签名)。
- **A2(绿)** `DigestDeps.isDownloaded` → `localOf`;`DigestArticle` 增 `dir?`/`contentPath?`/`warnings?`/`error?`。

### B · core:`fetchMissing`(同文件)

- **B1(红)** 新用例:
  - 只对 `downloaded: false` 的条目下载;**已下载的一次都不调 download**。
  - 成功 → `downloaded: true` + `dir` + `contentPath`(按注入的 `contentPathOf` 决定给不给)。
  - 失败 → 仍 `downloaded: false` + `error`,**条目不消失**。
  - 下载返回的 `warnings` 并入条目。
  - **串行**:并发数恒为 1(频控纪律)。
  - 进度回调按顺序触发,带「第几篇/共几篇 + 标题」。
  - 空清单 / 全部已下载 → 不调 download,原样返回。
- **B2(绿)** 实现 `fetchMissing(articles, deps)`;返回新数组,不原地改(便于测和排查)。

### C · CLI 接线(`src/cli/index.ts`)

- **C1** `digest` 加 `--download` / `--formats <csv>` / `--no-video`。
  - `--formats` 缺省 = `settings.defaultFormats`(**与 crawl 的硬编码缺省有意不同,注释写明**)。
  - 未带 `--download` 时**根本不构造下载依赖**(决策 1 的落点)。
  - stderr 两个阶段分开:查列表 `[3/16] 某号 … 2 篇`;下载 `↓ [2/5] 标题`。
- **C2** `localOf` 用已读进内存的库列表实现(v0.8.4 那两个 Set 扩成一个 Map,顺带保留 url 兜底)。
- **C3** `tests/cli/cli-contract.test.ts`:`--download` 出现在 `digest -h`;
  非法日期仍在鉴权前挡下(不因新 flag 改变顺序)。

### D · skill 同步(交付物)

- **D1** `SKILL.md` 速查表那行补 `--download`(一句话说清它给本地路径)。
- **D2** `references/commands.md`:`--download`/`--formats`/`--no-video` 的契约,
  输出里 `dir`/`contentPath` 的含义与「什么时候没有 contentPath」。
- **D3** `references/recipes.md`:第 5 条链路**改成一步到位**,
  **删掉「先 digest 再逐个 download」的旧写法**——并列会让 agent 继续用累的那条。
