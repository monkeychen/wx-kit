# v0.9.0 产品边界重置与安全维护实现计划

> 实施日期：2026-08-08。
>
> 本计划承接已完成的 M49。v0.8.6、v0.8.7 均不对外发布，下一公开版本直接为 v0.9.0。
>
> 状态：已完成实现与本地验收；未 push、未打 tag、未发布。

## 1. 目标

v0.9.0 不是普通补丁，而是 wx-kit 的产品边界重置：

- 核心输入收缩为用户明确提供的微信公众号文章 URL；
- 公众号发现、后台登录、按公众号抓取和订阅能力正式退场；
- 保留 M44–M47 中对当前 URL 下载仍有价值的 Chromium 请求栈与安全边界；
- 完成 M49 已实现的界面、后台、CLI 和测试退场；
- 刷新并处置当前真实 Dependabot 告警；
- 以当前有效 GUI、真实文章下载和打包应用重新验收。

本轮只完成代码和本地版本准备，不 push、不打 tag、不创建 GitHub Release、不更新 brew tap。

## 3. v0.9.0 剩余实现

### Task 3：刷新实时安全事实

- 使用 GitHub Dependabot API 重新读取 open/dismissed 告警，记录查询时间、包、严重级别、依赖范围和补丁版本。
- 不沿用 2026-07-28 的 23 条或之后口头提到的 28 条旧快照。
- 对每条告警判断当前 Electron SPA、CLI、运行时或构建路径是否可达。
- 先写清升级方案，再修改依赖。

### Task 4：依赖升级

- 能通过 patch/minor 修复的运行时、开发依赖全部升级。
- 对需要 major 且当前代码路径不可达的告警，不盲目升级；保留明确的处置理由。
- 使用官方 npm registry 的审计结果作交叉验证；国内镜像不支持 audit API，不能把沉默当安全。
- 依赖升级不得改变 M49 的停用边界，不恢复任何私有后台入口。

### Task 5：当前有效产品说明与截图

- README 只展示当前有效页面：URL 下载、文库、阅读器、设置。
- 若加入截图，必须来自当前 v0.9.0 界面和真实文章数据态；不再展示按公众号下载或订阅页。
- 更新截图时写明具体版本，不承诺“后续 UI 一致”。
- 复核 `agent/wx-kit-skill/` 与 `wx-kit-compose`，不得再把停用命令作为可用能力。

## 4. 验收

按顺序执行：

1. `npm test`
2. `npm run lint`
3. `npm run typecheck`
4. `npm run test:e2e`
5. `npm run test:e2e:live-download`
6. `npm run build`
7. 启动打包后的 macOS `.app`，核实 GUI 正常；调用打包内层 CLI，验证停用命令和真实 URL 下载。
8. 重新读取 Dependabot 告警，核实升级结果而不是推测结果。
