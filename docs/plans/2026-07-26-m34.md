# M34 实现计划 — 订阅检查反馈(v0.8.2 R1)

> 对应 `docs/PRD-v0.8.2.md` R1。分支 `feat/m34`。
> 性质是**准 bug**:IPC 层丢了返回值,导致渲染层想提示也无从提示。不是加 toast,而是把「逐号明细」这条数据通路打通。

## 已核实的事实(实现按这些来,不再回头查)

- **`RunCheckResult` 只有汇总数**:`{ accounts, newFound, failed, failures?, note?, authExpired }`(`electron/services/subscription-check.ts:23`)。逐号结果在函数内的 `results` 循环里就地消化掉了,**没往外传**。
- **IPC 丢返回值**:`ipc.ts:288` `ipcMain.handle('subscriptions:checkNow', async (_e, fakeids?) => { await runSubscriptionCheck('manual', fakeids) })`;本地包装 `runSubscriptionCheck`(`ipc.ts:245`)的返回类型也是 `Promise<void>`,`checkInFlight: Promise<void> | null`——**结果在两层都被丢**。
- **共享 in-flight 语义**:`checkInFlight` 让重叠的检查并入同一次运行(`ipc.ts:244` 注释)。改成返回结果后,**并入者拿到的是那一次运行的完整结果**(可能包含它没请求的号)。这是正确行为,渲染层按 fakeid 取自己关心的行即可,多出来的行照常显示(它们确实被检查了)。
- **自动下载不发进度**:service 里自动下载调 `downloadRefs(refs, formats, source)`(`subscription-check.ts:65`)——**没传第 4 参**。而 ipc 的 `downloadRefs` 实际签名是 4 参,第 4 参 `onProgress?: (e: ProgressEvent) => void`(`ipc.ts:228`),`RunCheckDeps.downloadRefs` 的类型只声明了 3 参(`subscription-check.ts:16`)。**通路是通的,只差声明 + 传参**。
- **手动下载进度走 `event.sender`**(`ipc.ts:295`),定时自动检查**没有 event.sender** → 自动下载的进度必须**广播**(仿 `emitSubsUpdated` 的 `BrowserWindow.getAllWindows()` 循环,`ipc.ts:214`)。
- **渲染层进度只认「自己触发的那个号」**:`Subscriptions.tsx:23-26` 用 `dlRef.current` 比对 fakeid,`dl` 为 null 时事件被丢弃 → 自动下载的进度即便发了也显示不出来。**要把 `dl` 从单个改成按 fakeid 的 map**,手动/自动共用一套(PRD:不新造机制)。
- **`busy` 语义**:`Subscriptions.tsx:134` `const busy = dl !== null`,用于下载期间置灰所有行的操作 + 顶部按钮 `disabled={dl !== null}` + Switch `disabled`。改 map 后 `busy` = map 非空。
- **策略读取**:`api.getSettings()` 已存在(`api.ts:39`),字段 `subscriptionNewArticleAction: 'prompt' | 'download'`。Subscriptions.tsx 当前不读 settings,要加。
- **跨页跳转**:`App.tsx` 用 react-router-dom(`Routes/Route`)→ 用 `useNavigate()`。
- **文库按公众号筛选是内部 state**:`Library.tsx:28` `const [account, setAccount] = useState<string | null>(null)`,无 URL 参数支持 → 「去看看」要落地到筛选,需给 Library 加一次性读 `?account=` 的能力(`useSearchParams`)。
- **CLI check-now 输出**:见 `src/cli/index.ts` 的 `subscription check-now`,当前输出汇总字段;要加 `results`。

## 步骤(bite-sized,TDD,每步跑 `npm test`)

### A · 核心通路:逐号明细(先把数据打通,UI 之后)

- **A1(红)** `tests/electron/subscription-check.test.ts` 加断言:
  - 「仅提示」模式,两个号各有 2/0 篇新文章 → `result.results` 为
    `[{ fakeid:'a', nickname:'甲', ok:true, newFound:2, downloaded:0 }, { fakeid:'b', nickname:'乙', ok:true, newFound:0, downloaded:0 }]`。
  - 「自动下载」模式,一个号 3 篇 → 该行 `{ newFound:3, downloaded:3 }`。
  - 某号失败 → `{ ok:false, error:'<原因>', newFound:0, downloaded:0 }`,且与既有 `failures`/`failed` 汇总**同时**成立(向后兼容)。
  - `no-session` / `no-accounts` / `auth-expired` 三条早退路径:`results` 为 `[]`(不是 undefined),汇总字段与 note 不变。
- **A2(绿)** `subscription-check.ts`:
  ```ts
  export interface PerAccountResult {
    fakeid: string; nickname: string; ok: boolean
    newFound: number      // 本次发现几篇新文章
    downloaded: number    // 其中自动下载了几篇(仅 download 策略下 >0)
    error?: string
  }
  export interface RunCheckResult {
    accounts: number; newFound: number; failed: number
    failures?: CheckFailure[]; note?: string; authExpired: boolean
    results: PerAccountResult[]   // 逐号明细(M34;早退路径为空数组)
  }
  ```
  在 `for (const r of results)` 循环里逐条 push;三条早退 return 补 `results: []`。
  `RunCheckDeps.downloadRefs` 类型加第 4 参:`onProgress?: (e: ProgressEvent) => void`。
- **A3(绿)** service 自动下载分支加进度转发:`RunCheckDeps` 加
  `onDownloadProgress?: (e: { fakeid: string; total: number; done: number; phase: string }) => void`;
  自动下载处改为
  ```ts
  const total = r.newRefs.length
  deps.onDownloadProgress?.({ fakeid: r.fakeid, total, done: 0, phase: 'start' })
  await downloadRefs(r.newRefs, settings.defaultFormats, source,
    (e) => deps.onDownloadProgress?.({ fakeid: r.fakeid, total, done: e.completed, phase: e.phase }))
  deps.onDownloadProgress?.({ fakeid: r.fakeid, total, done: total, phase: 'done' })
  ```
  单测:mock `downloadRefs` 调一次 onProgress → 断言 onDownloadProgress 收到 start/中间/done 三段且带正确 fakeid。

### B · IPC:把结果送出去(修掉丢返回值)

- **B1** `ipc.ts`:`checkInFlight: Promise<RunCheckResult> | null`;本地 `runSubscriptionCheck` 返回类型改 `Promise<RunCheckResult>`,内部 `return result`(`subsAuthExpired` 赋值逻辑不动)。
- **B2** `ipc.ts`:加广播 helper(仿 `emitSubsUpdated`),并把它接给 service:
  ```ts
  const broadcastDlProgress = (e: { fakeid: string; total: number; done: number; phase: string }) => {
    for (const w of BrowserWindow.getAllWindows()) if (!w.isDestroyed()) w.webContents.send('subscriptions:download:progress', e)
  }
  ```
  传入 `svcRunSubscriptionCheck` 的 deps:`onDownloadProgress: broadcastDlProgress`。
  **复用既有 channel**,渲染层不必区分手动/自动来源。
- **B3** `subscriptions:checkNow` 改为 `return await runSubscriptionCheck('manual', fakeids)`;
  `preload.ts` 无需改(invoke 本就回传);`api.ts` 的 `subscriptionsCheckNow` 返回类型 `Promise<void>` → `Promise<RunCheckResult>`,并 export `PerAccountResult` 类型给渲染层。
- **B4** `SubscriptionScheduler` 的 `runCheck: () => runSubscriptionCheck('auto')` 现在返回 result 而非 void —— 核实 scheduler 的 `runCheck` 类型签名,若声明为 `() => Promise<void>` 需放宽为 `Promise<unknown>` 或同步改类型(**不要**在这里 `.then(() => {})` 掩盖类型)。

### C · 渲染层:反馈落在被操作的对象上

- **C1** 进度 state 改 map:
  ```ts
  const [dls, setDls] = useState<Record<string, { total: number; done: number }>>({})
  ```
  事件处理:无条件按 fakeid 写入(`phase === 'done'` 时延迟清除该 key,或由结果态接管);
  `busy` = `Object.keys(dls).length > 0`;`downloadingThis` = `dls[a.fakeid] != null`。
  删掉 `dlRef` 的 fakeid 匹配逻辑(手动下载改为写同一个 map)。
- **C2** 行内结果态:
  ```ts
  const [rowRes, setRowRes] = useState<Record<string, PerAccountResult>>({})
  ```
  `checkNow`/`checkOne` 拿到 result 后 `setRowRes(Object.fromEntries(result.results.map(r => [r.fakeid, r])))`,
  **8 秒后淡出**(`setTimeout` 清空;失败态不自动清,留到下次检查——失败信息值钱)。
  行内文案(接在 actions 前):
  - `✓ 已自动下载 N 篇` + `[去看看]`
  - `发现 N 篇待处理`(仅提示模式,与既有「下载 N 篇/忽略」按钮并存)
  - `暂无新文章`
  - `✗ <error>`(常驻)
  `data-testid="subs-row-result"` 供 e2e。
- **C3** 单号 vs 全量的差异:
  - `checkOne`:**不弹任何全局 message**(反馈已在行内)。
  - `checkNow`:结束后 `message.info`(或 success)一条汇总——`查 N 号 · 新 M 篇 · 已自动下载 K 篇`(自动下载模式)/ `查 N 号 · 新 M 篇待处理`(仅提示);`failed>0` 时用 warning 并附「失败 N,详见检查记录」。
  - 早退 note 的话术:`no-session` → 「需重新登录公众号后台」;`no-accounts` → 「没有已订阅的公众号」(单号检查时若该号未订阅也会走到这条,文案要通用)。
- **C4** 策略常驻可见:
  - 载入时 `api.getSettings()` 取 `subscriptionNewArticleAction`,存 state;`onSubscriptionsUpdated` 时一并刷新(设置页改了策略后订阅页要跟上——**核实 settings 保存是否 emit 该事件;若不 emit,就在页面 focus/进入时重读**,不新造事件)。
  - 「检查全部」旁一行常驻:`发现新文章时:自动下载 ⚙` / `发现新文章时:仅提示 ⚙`,`⚙` → `navigate('/settings')`。`data-testid="subs-policy"`。
- **C5** 「去看看」直达文库:
  - `Subscriptions.tsx`:`navigate('/library?account=' + encodeURIComponent(a.nickname))`。
  - `Library.tsx`:`const [sp] = useSearchParams()`,首次挂载时若有 `account` 参数则 `setAccount(sp.get('account'))`(**一次性消费**:随后用 `setSearchParams({}, { replace: true })` 清掉,避免用户手动切筛选后刷新又被参数覆盖)。
