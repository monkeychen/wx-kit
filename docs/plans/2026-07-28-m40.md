## 已核实的事实(2026-07-27/28 读代码)

**R4 相关**

- `newRefs: ArticleRef[]` **已经存着完整信息**(title/url/createTime/itemShowType/appmsgid/itemidx),
  UI 只用了 `.length`(`Subscriptions.tsx:213/216/231`、`MainLayout.tsx:20`)。零额外请求。
- **水位与 pending 是两件事**:`updateWatermark(r.latest)` 在存 newRefs **之前**就执行了
  (`subscription-check.ts:83`),水位已越过全部新文章。所以部分下载/忽略/留着都不影响水位,
  也不会被下次检查重复发现;`ipc.ts:331` 那次 `updateWatermark` 实际是 no-op。
- **`setNewRefs` 是整体覆盖**(`subscriptions.ts:113`)。今天用户只能全下或全忽略,pending 不留存,
  看不出问题;**R4 一旦允许「留着回头看」,下次检查发现任何新文章就会把留存的整批冲掉**。
- 只在「提示」模式下有 pending:自动下载模式下完即 `clearNewRefs`(`subscription-check.ts:98`)。
- CLI 的 `subscription list` **已经把 newRefs 整个吐出来了**(`src/cli/index.ts:335`),agent 侧无缺口。

**R5 相关**

- `kindLabel` 是 `ArticleCard.tsx:22` 的私有函数:`5→视频 / 10→文字 / 8→图文 / 其余→''`。
  **`8` 是小绿书(图片消息),标成「图文」与「不标 = 普通图文」直接冲突**。
- 未知 `itemShowType` 返回 `''`,与普通图文在卡片上无法区分——而它恰恰走的是兜底解析。
- **⚠️ 与 PRD 记的不一致(以此处为准)**:`warnings` **根本没进 meta.json**——
  `buildMeta`(`export-meta.ts:20-30`)不写它,`ArticleMeta` 也没有该字段。
  它只经 `deps.onWarning` 汇进 `DownloadItemResult.warnings`,**只有 CLI 的 JSON 输出看得到**;
  GUI 的下载页与文库都不显示。**所以真实情况比 PRD 写的更糟:GUI 模式下告警彻底消失**,
  下载完成、告警产生、没有任何人看得见。
  → 因此「让 warnings 可见」必须先**持久化**,否则事后没有可显示的数据。
- 老文章没有 `itemShowType` 字段(M36 之前下的)。**null/undefined 必须不标**,
  否则整个存量文库会一片 ⚠(非目标里已写明不做回填)。

## 设计决策

1. **ref 的身份用 `mid_idx`**(`appmsgid`/`itemidx`),缺失时退回 url。与文库判重同源
   (AGENTS.md:「文章 id 是 `mid_idx`」),**不另造一套**。
2. **`setNewRefs` 改为合并**,并改名 `addNewRefs` 让语义写在名字上;
   去重后按 `createTime` 降序(最新的在上,与文库默认序一致)。
3. **勾选默认全选**:最常见路径仍是一键下全部。默认不选会把「全下」从 1 次点击变成 N+1 次。
4. **一次只有一个含义**:行内动作**始终作用于当前选择**——收起时选择即全部,
   文案照旧「下载 3 篇新文章」;展开后随勾选变成「下载所选 2 篇」。
   不并列摆「下载全部」与「下载所选」两套按钮。
5. **标题点击开原文**(外部浏览器):光看标题常判断不了值不值得下,这是「有选择」能成立的前提。
6. **R5 的类型文案上提 `core/message-kind.ts`**,返回 `{ text, warn }` 而不是裸字符串
   ——未知类型要的是**警示态**,让调用方决定怎么标,而不是把 emoji 焊死在 core 里。

## 步骤(bite-sized,TDD,每步跑 `npm test`)

### A · ref 身份与合并(core)

- **A1(红)** `tests/core/subscription-refs.test.ts`:
  - `refId(ref)`:有 `appmsgid`/`itemidx` → `"mid_idx"`;缺失 → url 原样。
  - `mergeNewRefs(existing, incoming)`:
    - 留存的 pending **不被冲掉**(既有 2 条 + 新来 1 条 = 3 条)——**本步的核心**。
    - 同一篇(同 mid_idx)不重复;**incoming 的字段覆盖 existing**(标题可能改过)。
    - 结果按 `createTime` 降序。
    - existing 为空、incoming 为空的边界。
  - `removeRefs(refs, ids)`:按 refId 精确移除,不误伤;空 ids 返回原数组。
- **A2(绿)** 实现 `src/core/subscription-refs.ts`。

### B · 存储改合并(`src/core/subscriptions.ts`)

- **B1(红)** `tests/core/subscriptions.test.ts` 增:
  - `addNewRefs` 两次调用后是并集(不是后者覆盖)。
  - `removeNewRefs(fakeid, ids)` 只删指定的,其余仍在;**全删后等价于 clear**。
  - `lastCheckedAt` 的写入行为不变(M34 修过的,不得回归)。
- **B2(绿)** `setNewRefs` → `addNewRefs`(合并);新增 `removeNewRefs`;`clearNewRefs` 保留
  (自动下载模式仍用)。改 `subscription-check.ts:101` 的调用点。

### C · IPC 支持子集(`electron/ipc.ts`)

- **C1** `subscriptions:downloadNew(fakeid, ids?)`:`ids` 省略 = 全部(现有调用方不动)。
  下载完只 `removeNewRefs(选中的)`,**不再无脑 clear**——否则未选中的会被顺手清掉。
- **C2** `subscriptions:dismissNew(fakeid, ids?)`:同上。
  那次 no-op 的 `updateWatermark` 保留但补注释说明它为何是 no-op(免得下次有人以为忽略靠它实现)。
- **C3** preload / `api.ts` 的签名加可选 `ids`。

### D · 类型文案上提(`src/core/message-kind.ts`)— R5

- **D1(红)** `tests/core/message-kind.test.ts` 增 `kindTag(t)`:
  - `0` / `11` → `null`(**默认类型不标,标了等于没标**)。
  - `null`/`undefined` → `null`(老文章没这个字段,**不能一片 ⚠**)。
  - `5` → `视频`、`10` → `文字`、**`8` → `图片`**(不再是与默认类型同名的「图文」)。
  - 未知数字(如 `99`)→ `{ text: '未知类型', warn: true }`。
- **D2(绿)** 实现;`ArticleCard.tsx` 改用它,删掉私有 `kindLabel`;`.kind-tag.warn` 加样式。

### E · warnings 持久化并可见 — R5

- **E1(红)** `tests/core/exporter.test.ts`(或 export-meta 相应用例):
  - 解析告警与视频失败告警**都**进 `meta.warnings`。
  - 无告警时**不写该字段**(与 `itemShowType`/`videos` 同样的「有才写」惯例,避免全库多一个空数组)。
- **E2(绿)** `ArticleMeta` 增 `warnings?: string[]`;`exportArticle` 收集后写入 meta
  (注意**视频告警在 `buildMeta` 之后产生**,要在写 meta 前补上,不能只用 `parsed.warnings`)。
- **E3** `ArticleCard`:有 warnings 时显示 `⚠`,`title` 给全文(hover 可读)。
  **强度到此为止**——PRD 只要求「必须能找到」,不是弹窗。

### F · 订阅页展开与勾选(`Subscriptions.tsx`)— R4

- **F1** 行内新增展开开关:`▸ N 篇新文章`;**收起时版面与今天完全一致**。
- **F2** 展开面板:每篇一行 = 勾选框 + 标题(点击开原文)+ 发布时间 + 类型标(复用 D 的 `kindTag`)。
  默认全选;选择态按 fakeid 存,收起不丢。
- **F3** 行内动作作用于当前选择(决策 4):`下载所选 N 篇` / `忽略所选 N 篇`;
  一篇都没勾时置灰(而不是静默什么都不做)。
- **F4** 下载进度沿用既有那套,`total` 为所选篇数。
