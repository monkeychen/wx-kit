# M41 实现计划 — CLI `subscription digest`:某一天各订阅号发了什么(v0.8.4 R2)

> 对应 `docs/PRD-v0.8.4.md` R2。分支 `feat/m41`。
> **skill 同步是交付物不是附属**——这条命令的唯一入口就是 skill,不写 = agent 不知道有它 = 功能不存在。

## 已核实的事实(2026-07-28 读代码)

- `listArticles(mpFetch, token, fakeid, { from, to })` **已支持日期范围**,且会在 `createTime < fromTs`
  时提前返回(不必翻完整个号)。过滤读者不可见的文章已在 `fetchPage` 内做掉(M38)。
- `Library.has(id)` 走 `canonicalId` 比较 —— 老库的 `mid_idx_sn` 与新的 `mid_idx` 认作同一篇,
  所以「是否已下载」不必迁移库就能判准。
- 没有现成命令能干这事:`library list/search` 查已下载的、`check-now` 按水位查「有没有新的」、
  `crawl --from/--to` 是单号且会下载。
- 成本:本机 16 个已订阅号 → 16 次请求、约 30–60 秒(串行 + 随机延迟,频控纪律不破)。
- **`SKILL.md` 的速查表有个既有排版 bug**:第 70–74 行把一段说明插进了表格中间,
  于是表格在那里断开,后两行(`settings` / `site sync`)**渲染成了普通文本**。顺手修掉。

## 设计决策

1. **CLI 只认 `YYYY-MM-DD` / `today` / `yesterday`**,自然语言由 agent 换算(PRD 已定)。
   非法输入**明确报错并给格式提示**,绝不猜——猜错会静默给出另一天的结果,比报错糟得多。
2. **纯查询**:不下载、不写库、不推水位。`check-now` 是「检查更新」,`digest` 是「看看那天有什么」,
   语义分开,共用水位只会互相污染。
3. **`downloaded` 字段是这条命令的价值所在**:它把「发现」与「已有」连起来,
   agent 拿到清单即可分流,不必再查一次库。
4. **失败不阻断**:某号失败(频控/登录态)进 `failures`,其余照常返回,**退出码仍 0**
   ——部分成功就是成功,让 agent 自己看 `failures` 决定要不要重试。
   唯一的例外:**一个号都没查成**时退出码 1(那不是部分成功,是失败)。
5. **进度走 stderr**:16 个号半分钟无输出会像卡死。

## 步骤(bite-sized,TDD,每步跑 `npm test`)

### A · 日期解析(`src/core/digest-date.ts`,新文件)

- **A1(红)** `tests/core/digest-date.test.ts`:
  - `2026-07-23` → 原样;`today`/`yesterday`(大小写不敏感)→ 按注入的 `now` 算。
  - `7月23日` / `昨天` / `2026-7-3` / `20260723` / 空 → **报错**,错误文案含期望格式。
  - 非法日历日(`2026-02-30`)→ 报错(`Date.parse` 会静默滚到 3 月,必须显式挡)。
  - 返回值同时给出当天的 `[fromTs, toTs]`(本机时区),避免调用方各算各的。
- **A2(绿)** 实现 `resolveDigestDate(input, now)`。

### B · 汇总编排(`src/core/subscription-digest.ts`,新文件)

- **B1(红)** `tests/core/subscription-digest.test.ts`(依赖全注入,无网络):
  - 多个号串行查,合并结果并**按发布时间降序**(跨号统一排序,不按号分组——
    用户问的是「那天发了什么」,不是「每个号发了什么」)。
  - `downloaded` 依 library 判定:已下载 true、未下载 false;**老库的 `mid_idx_sn` 也认**。
  - 某号抛错 → 进 `failures`,其余号照常;`ok` 仍为 true。
  - **全部号都失败** → `ok: false`(调用方据此给退出码 1)。
  - 逐号进度回调按顺序触发(给 stderr 用)。
- **B2(绿)** 实现。**不在这里做频控退避**——`listArticles` 内部已有串行 + 随机延迟。

### C · CLI 接线(`src/cli/index.ts`)

- **C1** `wx-kit subscription digest --date <...> [--accounts <csv>]`。
  - 无登录态 → 与其它需要 session 的命令同样的 `AUTH_REQUIRED`(退出码 2),**不要自造一套**。
  - stderr 逐号进度:`[3/16] 数字生命卡兹克 … 2 篇`。
  - stdout 输出 PRD 定的结构(`ok/date/accounts/count/articles/failures`)。
- **C2** `tests/cli/cli-contract.test.ts`:`digest` 出现在 `subscription -h`;
  **`--date` 缺失时报用法错(退出码 2)**,不是静默当今天。

### D · skill 同步(**交付物,不是文档**)

- **D1** `SKILL.md` 速查表加一行,并**注明日期由 agent 换算**;顺手修掉表格断裂的排版 bug。
- **D2** `references/commands.md`:完整输出契约,逐字段说明,重点讲 `downloaded`/`id` 怎么用;
  `--accounts` 与耗时提示;非法日期会报错。
- **D3** `references/recipes.md`:一条完整链路范例——「昨天各号发了什么」→ agent 自己算日期 →
