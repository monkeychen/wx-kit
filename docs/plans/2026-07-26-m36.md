# M36 实现计划 — 列表接口修正 + 消息类型一等公民(v0.8.2 R4)

> 对应 `docs/PRD-v0.8.2.md` R4。分支 `feat/m36`。
> 两层:①**换列表接口**(修 bug:漏掉整类消息,订阅静默漏检)②**解析按类型分发**(防下一个静默 bug)。

## 已核实的事实(2026-07-26 真实 session 实测)

### 1. 用错了接口

| 接口 | 总数 | 最新 | 类型 |
|---|---|---|---|
| `cgi-bin/appmsg?action=list_ex&type=9`(现用) | 370 | 2026-07-17 | 只有 `item_show_type=0` |
| `cgi-bin/appmsgpublish?sub=list&sub_action=list_ex&type=101_1&free_publish_type=1` | **770** | **2026-07-25** | 0 / 5 / 10 齐全 |

`type` 换 `0`/空/`101` 一律 `ret=200002` 参数错误 —— 旧接口没有「取全部类型」的开关,只能换接口。

### 2. `appmsgpublish` 的数据结构(三层嵌套,中间两层是 **JSON 字符串**)

```
json.publish_page                     → JSON 字符串
  → { total_count, publish_list[] }
       publish_list[i].publish_info   → JSON 字符串
         → { appmsgex[] }             ← 文章在这里
```
`appmsgex[]` 每项字段(实测):
`title, link, create_time, update_time, item_show_type, itemidx, appmsgid, digest, cover, author_name, is_deleted, media_duration, …`

- **`begin`/`count` 按「群发组」计,不是文章数**:`count=20` → `publish_list.length === 20`;
  一次群发多篇时该组 `appmsgex` 有多项。**游标必须按组数推进**(沿用现有 `pageLen` 的教训:
  按固定步长推进会跳文章)。
- `total_count = 770` 是**组总数**。
- `media_duration` 不可用于判类型:普通图文也带 `"0:00"`。
- `is_deleted` 需过滤。

### 3. `fetchPage` 是唯一的接口调用点

`listArticles`(批量抓取)与 `listArticlesSince`(订阅检查)共用它 —— **改这一处,两条链路同时修好**。
这也是订阅一直静默漏检的原因:它跟抓取用的是同一个被过滤的列表。

### 4. `appmsg_type` 与 `item_show_type` 是正交的两个维度

安哥举证的 `9APk0OGkpfVXGvOkH641Qw`:`appmsg_type=10002`(视频类)+ `item_show_type=10`(文字消息形态)
+ 确实带 `mp_video_trans_info`。**M35 的 `isVideoMessage()` 把两者当同一个枚举判,对这种混合体不准。**

正确的切分:
- **`item_show_type` 决定「正文怎么取」**(文字消息读 `text_page_info`,图文消息读 `picture_page_info_list`,普通图文读 `#js_content`)
- **视频是附加内容,独立提取**(`extractMpVideos` 不看类型,有就取)——和图片同级

### 5. 已知 5 种 `item_show_type`(开放集合)

`0` 普通图文 / `5` 视频消息 / `8` 图文消息(小绿书) / `10` 文字消息 / `11` 未定性(样例是发布通告,长得像图文)。
付费/音频/直播等大概率另有编号 —— **所以未知类型必须显式告警,不能静默兜底**。

## 步骤(bite-sized,TDD,每步跑 `npm test`)

### A · 列表接口(`src/core/mp-client.ts`)

- **A1** `ArticleRef` 加 `itemShowType?: number`(`mp-types.ts`)。可选,老调用方不受影响。
- **A2(红)** `tests/core/mp-client.test.ts` 加用例,喂**真实形状**的 `appmsgpublish` 响应
  (fixture `tests/fixtures/appmsgpublish.json`,从真实返回裁剪,含:一组多篇、一条 `is_deleted`、
  `ist` 为 0/5/10 各一条):
  - 返回的 `ArticleRef[]` 含全部类型,`itemShowType` 正确带出。
  - 一组多篇全部展开,顺序按 `itemidx`。
  - `is_deleted` 的条目被过滤。
  - `pageLen` 是**组数**(用于游标推进),不是展开后的文章数。
  - 顶层/中间层 JSON 字符串解析失败时不抛,返回空页(接口偶发脏数据不该炸整次抓取)。
- **A3(绿)** 重写 `fetchPage`:换端点与参数,三层解析,`total = total_count`。
  `checkRet(json)` 保持在最前(频控/登录态判定不变)。
- **A4** `listArticlesSince` 的注释与 `cap` 复核:旧接口每页实回 ~5 条才需要「翻到水位为止」,
  **新接口每页 20 条**,日常一次请求覆盖更深。逻辑不改(它本就按水位停),但注释要更新,
  别留着「微信每页实回 ~5 篇」这句过期结论误导后人。

### B · 消息类型一等公民(`src/core/parse-article.ts`)

- **B1** 新增 `src/core/message-kind.ts`(纯逻辑,可单测):
  ```ts
  export type MessageKind = 'article' | 'text' | 'picture' | 'video' | 'unknown'
  /** 从页面脚本读 item_show_type;读不到返回 null */
  export function readItemShowType(html: string): number | null
  export function kindOf(itemShowType: number | null): MessageKind
  ```
  映射:`0|11 → article`、`5 → video`、`8 → picture`、`10 → text`、其他/null → `unknown`。
  (`11` 归 article:实测它有 `#js_content` 且下载正常;归错了也只是走兜底,有告警兜底。)
- **B2(红/绿)** `parseArticle` 改为**按 kind 分发**,替掉现有猜测链:
  - `article`:`#js_content`(现状)
  - `text`:`text_page_info.content` → 段落 + 首行生成标题
  - `picture`:`content_noencode` + `picture_page_info_list`
  - `video`:`content_noencode`(M35 的处理)
  - `unknown`:**按 article 兜底,但产出告警**「未识别的消息类型 N,按普通图文处理」
- **B3** **`#js_content` 内容可疑时也告警**:兜底路径下若 `#js_content` 含 `<script` 或长度异常
  (M35 那 21.8 万字符垃圾的特征),同样进告警 —— 类型判对但页面结构变了也能被发现。
- **B4** 视频提取**与类型解耦**:`extractMpVideos(html)` 照旧无条件跑(和图片同级)。
  删掉 M35 的 `isVideoMessage()`(它混用了两个维度),改由 `kindOf` 统一判定。
- **B5** `ParsedArticle` 加 `itemShowType: number | null` 与 `warnings: string[]`;
  `ArticleMeta` 加 `itemShowType?: number`。解析层的告警经 `exportArticle` 汇入既有
  `deps.onWarning`(M35 已建好这条通路),最终出现在 `DownloadItemResult.warnings[]`。

### C · 让类型可见

- **C1** 文库卡片/行:非普通图文的显示类型标识(「视频」「文字」「图文」),同 M35 的 📹 角标一处渲染。
- **C2** `meta.json` 含 `itemShowType`(agent 可据此筛选)。
- **C3** `agent/wx-kit-skill/`:`ArticleMeta` 字段表加 `itemShowType` + 五种取值说明;
  `warnings[]` 补一句「未识别消息类型也会出现在这里」。
