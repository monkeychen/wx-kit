## 步骤(bite-sized,TDD,每步跑 `npm test`)

### A · 版本比较(`src/core/version-compare.ts`,纯逻辑)

- **A1(红)** `tests/core/version-compare.test.ts`:
  - `compareVersions('0.8.10', '0.8.9') > 0` ← **钉死这条**:字符串比会判反,而这个 bug 要等到
    发 0.8.10 才爆(那时没人会想到是比较函数的问题)。
  - `v` 前缀两侧都能带:`compareVersions('v0.9.0', '0.8.1') > 0`。
  - 位数不等:`compareVersions('0.9', '0.9.0') === 0`、`compareVersions('1.0', '0.9.9') > 0`。
  - 相等返回 0;非法输入(空串/`abc`)不抛异常,按 0 段处理。
  - 预发布后缀**只做剥离不做排序**:`compareVersions('0.9.0-beta.1', '0.9.0') === 0`
    —— 项目从未发过 pre-release,先不引入 semver 的完整优先级规则(YAGNI),
    但要**注释写明**这是已知简化,真要发 pre-release 时再补。
- **A2(绿)** 实现约 20 行:剥 `v`/预发布后缀 → `split('.')` → 逐段数字比,缺位视为 0。
  **不引 semver 依赖**(PRD 非目标已定)。

### B · 检查更新(`src/core/check-update.ts`,注入 fetch 便于单测)

- **B1(红)** `tests/core/check-update.test.ts`(注入假 fetch,不联网):
  - 有新版:`{ hasUpdate: true, latest: '0.9.0', notes: '…', assets: [...] }`。
  - 当前版本更高或相同 → `hasUpdate: false`(但仍返回 latest,供设置页显示「已是最新」)。
  - `draft: true` 或 `prerelease: true` 的 release → **视为无更新**(不该把草稿推给用户)。
  - HTTP 非 200 / 网络抛错 / JSON 缺字段 → 返回 `null`(调用方据此静默失败,不弹错)。
  - 超时:注入的 fetch 挂住时,`AbortSignal.timeout` 生效并返回 `null`。
- **B2(绿)** 实现:
  ```ts
  export interface UpdateInfo {
    current: string; latest: string; hasUpdate: boolean
    notes: string; publishedAt: string
    assets: Array<{ name: string; url: string; size: number }>
  }
  export async function checkUpdate(
    currentVersion: string,
    deps?: { fetchJson?: (url: string) => Promise<unknown>; timeoutMs?: number },
  ): Promise<UpdateInfo | null>
  ```
  超时默认 8 秒(PRD 定)。**失败一律返回 null,不抛**——启动时静默检查绝不能因为断网炸出错误。

### C · 安装渠道识别(`src/core/install-channel.ts`,注入依赖)

- **C1(红/绿)** `tests/core/install-channel.test.ts`:
  - mac + Caskroom 目录存在 → `'brew'`(两个前缀都测:`/opt/homebrew`、`/usr/local`)。
  - mac + 无 Caskroom → `'dmg'`。
  - win → `'nsis'`。
  - linux / 其它 → `'unknown'`。
  - **查目录而不 fork `brew list`**:后者慢且依赖 shell 环境(打包 app 里 PATH 常不全)。
- **C2** 升级动作文案由渠道决定,同在此模块(纯字符串,可单测):
  ```ts
  export function upgradeCommand(channel: InstallChannel): string | null
  ```
  brew → `brew update && brew upgrade --cask wx-kit && xattr -cr /Applications/wx-kit.app`
  —— **三段都不能省**:不 `brew update` 会读到本地 tap 的旧 cask;不 `xattr -cr` 未签名 app 连
  纯 CLI 都被 Gatekeeper 拦(AGENTS.md brew 陷阱①②)。**把我们踩过的坑固化成一条命令,是本里程碑最实的价值**。
  其它渠道返回 null(走下载资产的路径)。
- **C3** 资产挑选:`pickAsset(assets, platform, arch)` —— mac arm64 取 `-arm64.dmg`、mac x64 取 `.dmg`、
  win 取 `.exe`;挑不到返回 null(退回「打开 releases 页」)。用真实资产名做测试数据。

### E · IPC / preload / api

- **E1** `electron/ipc.ts`:
  - `update:check`(入参 `{ silent?: boolean }`)→ 调 `checkUpdate(app.getVersion())`;
    **每天最多自动查一次**:`silent` 且 `lastUpdateCheckAt` 在 24h 内 → 直接返回 null 不发请求;
    查完写 `lastUpdateCheckAt`。`updateCheckEnabled: false` 时 silent 调用直接返回 null(手动仍可查)。
  - `update:channel` → 返回 `{ channel, upgradeCommand }`。
  - `update:downloadAsset`(入参 asset url/name)→ 下到 `app.getPath('downloads')`,
    **复用 `fetchBinary` 的按体积超时**(dmg 140MB,同视频量级),下完 `shell.openPath`;
    进度经既有 `download:progress` 语义广播?**不复用**——那是文章下载的通道,混用会让下载页误显示。
    新开 `update:progress` 事件(仅此一处消费,清晰)。
- **E2** `preload.ts` + `api.ts`:`updateCheck(silent)` / `updateChannel()` / `updateDownload(asset)` /
  `onUpdateProgress(cb)`。
- **E3** 启动静默检查:`MainLayout` 挂载后延迟 3 秒调 `updateCheck({ silent: true })`
  —— **不阻塞首屏**,失败无声。
