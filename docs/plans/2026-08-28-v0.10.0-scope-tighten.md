# v0.10.0 边界收敛与订阅体验修复（已完成 2026-08-28）

> 背景：2026-08-27 spike 终局确认微信读书列表接口为服务端账号级封禁（见 AGENTS.md），
> 「按公众号批量下载历史」无解。安哥决策：①批量下载入口（GUI+CLI）停用；②订阅去重 + 可删除；
> ③行内「检查」不得触发全量检查的观感。分支 `feat/v0.10.0-weread-backend` 就地实施。
>
> 验收记录：474 单测 / lint / tsc / vite build 全绿；e2e ALL PASSED（含 mode-account 缺失断言、
> 订阅删除-再订阅撤销标记、行内检查只落本行结果）；真实 CLI `crawl` 输出
> `MP_BACKEND_UNAVAILABLE` + 退出码 2，零网络请求。

## T1 批量下载停用

| 层 | 改动 |
|---|---|
| GUI | `Download.tsx` 移除模式页签与 AccountMode，恢复单模式（按链接下载）；「照此再下」对历史里公众号事件改为回填该事件的**文章 URL 列表**到 URL 模式（链接永远可下，比死入口诚实）；删除 `AccountMode.tsx`、`CrawlProgress.tsx` |
| IPC | `mp:crawl` 命中 `RETIRED_PRIVATE_API_COMMANDS` 直接返回 retired 响应（零网络）；`mp:crawl:cancel` 一并移除；`mp:search` 保留（订阅识别仍用） |
| preload/api | 移除 `mpCrawl`/`mpCancelCrawl`/`onCrawlProgress` 及 `CrawlEvent` 类型 |
| CLI | `crawl` 命令顶部命中 retired 集合 → `retiredPrivateApiResponse()` 退出码 2；`RETIRED_PRIVATE_API_COMMANDS = {crawl}`；help 文案同步 |
| 保留 | `crawlAccount` core 逻辑、`wereadCrawlListFn`（digest 依赖）、下载历史中旧公众号事件的展示 |

## T2 订阅去重 + 可删除

| 层 | 改动 |
|---|---|
| core `subscriptions.ts` | ① `safeNormalizeAccountId`：读入/合并时把 base64 老形态归一成 `MP_WXS_*`（非法形态原样保留）；② `list()` 读入时按归一 id 合并重复（水位取 max、newRefs 合并、昵称取非空）；③ 文件加 `removedFakeids?: string[]`；④ 新增 `removeAccount(fakeid)`：写删除标记 + 从 accounts 移除；`addAccount` 清除该标记；⑤ `mergeAccounts` 过滤带删除标记的历史派生行（否则删了会回来） |
| IPC/preload/api | `subscriptions:remove` → `subs.removeAccount`；preload `subscriptionsRemove` |
| GUI `Subscriptions.tsx` | 行动作加「删除」（Popconfirm 二次确认）；删除后 reload；行内不再出现同名重复行（归一生效） |

## T3 行内检查状态隔离

`Subscriptions.tsx`：`checking: boolean` 全局态拆为 `checkingIds: string[]`；行内「检查」只置本行；「检查全部」沿用全局态；行内 busy 文案只作用于对应行。后端 `fakeids` 过滤已确认无 bug，不改。
