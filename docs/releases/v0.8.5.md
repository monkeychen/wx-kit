# wx-kit v0.8.5 — 一个问题,一份清单(2026-07-28)

上一版给了「那天各订阅号发了什么」,但答案只到链接。**要真拿去用,还得自己逐个下载,
再把「刚下的」和「本来就有的」两种结果缝成一份清单**——那道缝本该由工具缝。

## 新增

**`subscription digest --download`:一条命令拿到能直接读的素材**

```sh
wx-kit subscription digest --date yesterday --download --formats md,meta
```

- **缺的下、已有的跳过**,清单里**每篇都带 `dir` 和 `contentPath`**
  ——不区分是刚下的还是本来就在库里的,拿到就能读正文。
- **`--formats` 缺省跟设置里的默认格式走**(不是固定的 `md,html,meta`,那是 `crawl` 的缺省):
  「我平时下什么就下什么」比记住一串字面量更符合直觉。想省流量可加 `--no-video`。
- **`contentPath` 只在正文文件真存在时才给**(下载时选了 `md`)。
  给一个指向不存在文件的路径比不给更糟——照着读会失败,还得回头猜为什么。
- **拿不到的那几篇仍留在清单里**:`unavailable: true` 是「读者本就打不开」(审核未通过/已删除),
  **重试无用**;只有 `error` 的是真故障(网络/频控),可以再试。这一区分让自动化不会对着死链反复重试。
- **不带 `--download` 时行为一字不变**:纯只读,不下载、不写库、不推进订阅水位。
  这不是靠一个 if 分支的自觉——查询与取内容在实现上就是两个独立步骤。
- **即使带 `--download` 也不推进订阅水位**。下载与水位无关,水位只由订阅检查推进。

配套的 agent 说明书(`agent/wx-kit-skill`、`agent/wx-kit-compose`)已同步:
原先「先 digest 再逐个 download」的范例**直接替换掉**,不并列——并列只会让人继续用累的那条。

## 验证

- 单测 518 → 531 全绿,tsc / lint 通过;图形界面端到端全套通过。
- **真机验证**(隔离库根 + 真实登录态,不碰主库):
  - 下好的文章按 `contentPath` **真读到正文**;同一条命令再跑,已下好的**一次请求都不发**,
    两轮输出逐字段一致。
  - `--formats meta` 时不给 `contentPath`(目录里确实只有 `meta.json`)。
  - 只读模式跑完,库根**没写任何东西**;订阅水位前后一致。
  - 真实数据里遇到两篇同名文章,下载才发现是**审核未通过后重发**——`unavailable` 正确标出。
- 打包后的 .app 实跑确认新参数可用。
