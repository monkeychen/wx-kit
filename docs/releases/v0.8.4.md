# wx-kit v0.8.4 — 看得见,还能挑(2026-07-28)

上一版的主题是「不让用户猜」——把系统知道的告诉你。这一版往前走一步:**光告知不够,得让你能据此做选择。**

五条需求是同一个形状:**系统手里已经有这个信息,你却用不上或用不准**。没有一条需要新抓数据。

## 修复

**有新版却一直不提示(R1)**

本机装着 v0.8.2、「启动时检查更新」开着、v0.8.3 已发布——等一小时也没动静。两处设计缺陷叠在一起:

- **限流把结论一起吞了**:24 小时内查过就直接返回空,而界面只能把「空」理解成「没有新版」。
  限流的本意是省请求,不是隐瞒结论。现在**被限流时给出上次查到的结果**,`hasUpdate` 按当前版本实时算
  ——所以升级后提示自动消失,不需要任何清理。
- **唯一的检查时机绑在「开窗后 3 秒」**:桌面应用常年开着,关掉窗口那段逻辑就不存在了,可能好几天都不查一次。
  改由主进程每小时问一次;**tick 变频繁不等于请求变频繁**,真正的节流仍是「每天最多一次」。

**类型标识把「图片」标成了默认类型的名字(R5)**

图片消息(小绿书)被标成「图文」——而「图文」恰恰是**不标标签的那个默认类型**的名字,于是
「标了图文的反而不是普通图文」。改为「图片」。普通图文仍然不标:文库里绝大多数是它,
全标一遍等于全不标,**标识的价值在于它出现时你就知道这篇不一样**。

同时:没见过的消息类型此前与普通图文在卡片上无法区分,现在给警示态标识;
解析告警(`warnings`)以前**在图形界面里根本不存在**——产生了、然后消失,只有命令行输出看得到。
现在写进 `meta.json`,卡片上一个 `⚠`,hover 可读全文。

## 新增

**订阅新文章:看得见是哪几篇,挑着下载或忽略(R4)**

此前每个号只显示一个数字,只能全下或全不要。**而这些标题早就存在本地了**——
完整的标题、时间、类型、文章主键一直躺在订阅记录里,界面只用了它的长度。零额外请求。

- 点开数字展开明细:标题 + 发布时间 + 类型标识;**点标题用浏览器打开原文**
  ——光看标题常常判断不了值不值得下,这是「有选择」能成立的前提。
- 勾选后下载或忽略;**默认全选**,所以最常见的「全下」仍是一次点击。
- 行内动作**始终作用于当前选择**:收起时选择即全部,展开后文案随勾选变化。
  一次只有一个含义,不并列摆「下载全部」和「下载所选」两套按钮。

**CLI:查订阅号某一天发了什么(R2)**

```sh
wx-kit subscription digest --date yesterday
```

不下载、不写库、**不推进订阅水位**——可以反复查同一天。这与「检查更新」是两件事:
后者按水位问「有没有新的」,查完要推水位;共用水位只会互相污染。

每篇带 `downloaded` 标记,把「发现」与「已有」连起来:已在库的直接读本地,没下的才下载。
日期只认 `YYYY-MM-DD` / `today` / `yesterday`,**「昨天」「7月23日」这类说法由调用方换算**
——CLI 刻意不猜:猜错会静默给出另一天的结果,而没人会发现。

**创作编排 skill 跟上了 CLI(R3)**

`agent/wx-kit-compose` 上次改动停在 2026-06-23(v0.4.0),中间隔了二十多个里程碑,
它认识的命令只有 `library export` 的四个选料器——**上下游两端都错过了**:
上游只能从已下载的文章开始,下游停在初稿。

现在:上游从 `subscription digest` 起步(「昨天各号发了什么」才是选题真正的起点),
下游可选 `site sync` 发到个人站点(**默认不做,需明确要求**——发布是不可逆的对外动作),
中间补上按关键词找素材、按发布时间取最近 N 篇,以及两个影响素材可用性的字段
(视频/文字消息没有长正文,据一段描述写论据等于编造)。

它落后二十个版本的根因是**把命令细节抄进了自己文件里**——抄来的不会跟着源头变。
所以这次没有抄得更全,而是把参数与输出契约一律指向 `wx-kit-skill`,并把这条教训写进它自己的避坑清单。

## 顺手修掉的既有缺陷(不在需求里,但同属被改动的路径)

- **订阅下载没透传文章主键** → 订阅拿到的是短链,只能退化成路径哈希 id,
  同一篇经「按公众号」抓时算成另一篇。**真实文库里已积下 32/267 篇**。
  这是 v0.8.2 为批量抓取修过的同一个 bug,当时漏了订阅这个调用点(图形界面与命令行各一处)。
- **留着没处理的新文章会被下次检查冲掉**:存新文章是整体覆盖。此前只能全下或全忽略所以看不出来,
  一旦能「留着回头看」就是静默丢数据。改为按文章主键合并。
- **下载失败的文章被静默清出待处理列表**——点了下载、失败了、列表里也没了,连重试入口都没有。
  现在只移除「成功 / 已在库 / 读者本就打不开(重试无用)」,真故障留下等重试并明确提示。
- `subscription digest` 的 `downloaded` 除了比 id 还比原文链接,否则上面那 32 篇会被误报成「未下载」,
  反倒诱导重下一遍——那正是这条命令最该避免的事。

## 验证

- 单测 479 → 518 全绿,tsc / lint 通过;Playwright 图形界面端到端全套通过(新增 10 条断言,零网络)。
- **真机验证**(隔离配置与库根、借真实登录态,不碰主库):
  - 复现原场景:限流状态 + 缓存里有新版 → 提示出现且**一次请求都没发**;关掉开关则既不请求也不提示。
  - 订阅展开看真实明细、部分下载(下 1 留 1)、短链下载后 id 恢复为文章主键。
  - `digest` 真跑:`downloaded` 与真实文库对得上(含旧格式 id),跑完订阅与文库记录**逐字节未变**。
