# v0.10.3 · 三个小修：CLI 入口守卫、文库筛选名称、识别反馈

发布日期：2026-09-08 · 里程碑 M57 · 需求/验收 `docs/PRD-v0.10.3.md`

## 修复与改进

### CLI wrapper 不再指向临时位置

- 从开发模式或构建目录（`release/` 产物）启动 app 时，「创建命令行快捷方式」会**拒绝执行并给出
  引导**——此前创建的 wrapper 指向临时产物，打包清理后 CLI 就悬空报错（v0.10.2 期间实录）。
- 设置页 CLI 区在临时位置时显示常驻说明；首启引导弹窗在临时位置不出现。
- 从正式安装（/Applications、brew、npm）启动时行为与此前完全一致。

### 文库筛选框显示公众号名称

- 修复 v0.10.2 的「文库」入口跳转后，筛选框显示一串公众号 ID 的问题：现在无论从哪里进入，
  筛选框显示的都是公众号名称。
- 筛选值改用公众号稳定身份（改名不失联），旧文章（无身份记录）按名称兜底，两段历史归并展示。
- 该号在文库 0 篇的专属空态下，筛选框同样正确显示名称。

### 订阅页「识别」全程有反馈

- 识别中按钮转圈、输入框禁用（此前是数秒无反应的盲等）。
- 空输入点击给引导话术；识别不出公众号（链接非公众号文章/已删）给明确提示——此前这两条路
  「点了没反应」。
- 识别失败与登录态过期的提示保持不变。

## 验证

- 574 项测试、lint、TypeScript 检查通过；GUI e2e 全绿（含 2 条 M57 新断言，`no console/page errors`）。
- CLI 守卫经打包产物实机验证：临时位置点创建出引导且 `~/bin/wx-kit` 不被改写。
- 阅读数获取经真机 spike 证伪（微信读书通道无计数字段），未列入本版，结论已留档防重复投入。

## 已知边界

- 微信读书每个公众号只返回最新一篇；两次刷新之间被覆盖的文章无法自动找回。
- macOS 安装包未签名、未公证；安装后仍需执行 `xattr -cr`。
- Windows CLI 的 stdout 仍需重定向到文件（`> out.json`）。
