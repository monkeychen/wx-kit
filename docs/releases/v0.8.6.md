# wx-kit v0.8.6 — 请求保护与全局频控治理

> 状态:实现与离线验收完成,尚未发布。
> 本版开发期间真实微信访问保持冻结,没有用当前账号/IP做登录、搜索、抓取或下载验证。

## 用户能感知到的变化

- 所有公众号后台、文章页、图片和视频请求现在共用一个全局队列,GUI 与 CLI 也共享同一份持久状态。
- 首次升级到本版会保护性暂停微信访问。用户可在“设置 → 微信请求保护”查看原因、排队数、上次请求和最早可执行时间,再明确恢复请求许可。
- 一旦识别到 `200013`、HTTP 429 或高置信频控/验证页面,系统立即全局熔断,停止订阅调度和后续队列,不会自动重试或定时探测恢复。
- `auth-status` 只查询本地是否保存登录态;`session import` 只导入并报告有效性未知。两个动作都不再隐藏访问微信。
- CLI 新增 `protection status|pause|resume`,用于查看、暂停或明确恢复全局请求许可。
- 设置页新增“公众号账号”:可重新扫码登录或彻底退出。重新登录会先清旧会话;
  退出会清本地 session、整个专用分区、连接、HTTP/认证缓存,但保留设置、订阅、文库、历史和频控状态。
- 任一登录态清理步骤失败都会明确提示并允许重试,不会在仍有残留时显示“已退出”。

## 请求一致性修复

- 微信后台 API、文章 HTML 与媒体资源统一改走扫码登录所属的 Electron Chromium Session。
- Cookie 以 Chromium Cookie Jar 为运行时真相;旧文件或跨机导入只在 Jar 为空时恢复,不会覆盖 Chromium 已更新的 Cookie。
- 删除固定伪装成 macOS Chrome 124 的 User-Agent,也不手写 Cookie 或 Client Hints;各平台使用自身 Chromium 会话的真实网络身份。
- 请求节奏集中到一个可测试的 governor,删除 crawl 的 30/60/90 秒频控重试和业务层散落的局部等待。
- 审计日志只记录脱敏 host/path、请求类别和放行/等待/拒绝决定,不记录 token、Cookie 或完整签名 URL。

## 离线验收

- `npm test`:573 项通过。
- `npm run lint`、`npm run typecheck`:通过。
- `npm run test:e2e`:全部通过;隔离 userData、只访问本机 fixture,微信请求尝试计数为 0。
- `npm run build`:macOS arm64/x64 未签名构建通过。

## 仍未验证的边界

- 尚未验证当前账号/IP的频控是否解除。
- 尚未用真实微信请求验证 Chromium Session 新链路的服务端兼容性。
- 尚未用真实账号验证“账号 A → 重新登录账号 B → 退出 → 重启后必须扫码”的完整链路。
- 本版减少客户端自身的矛盾指纹和无意流量,**不承诺“没有自动化痕迹”,也不保证以后一定不会被微信频控**。
- 真实 smoke 只有在用户明确解冻后才执行:单进程、一个人工触发动作、最多一次后台请求、零自动重试。
