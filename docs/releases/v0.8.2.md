# wx-kit v0.8.2 — 不让用户猜(2026-07-26)

四条需求的共同点是**系统知道、却没告诉用户**:点了检查不知道发生了什么、文章里的视频悄悄丢了、有新版本不知道、以及——查下去才发现的——**整类文章从来没被抓到过**。

## 修复

**订阅检查终于会说话(R1)**

「发现新文章时」设为**自动下载**后,点「检查」会静默把文章下走:页面毫无变化,只在日志里留一行。根因是实现遗漏——IPC 层把 `runSubscriptionCheck` 的返回值整个丢了,渲染层拿到 `undefined`,**想提示也无从提示**;而自动下载那条路径连一个进度事件都不发。

- 检查结果带**逐号明细**(哪个号新增几篇、下了几篇、失败原因),反馈**就地显示在被操作的那一行**,几秒后淡出;失败态留到下次检查。
- 自动下载现在有进度条,与手动下载**同一套 UI**(复用既有事件通道,没新造机制)。
- 下完给「去看看」直达文库并筛到该公众号——解决「东西下到哪了」。
- 单号检查不弹全局提示(反馈就近);「检查全部」额外给一条汇总。
- 订阅页常驻显示当前策略(「发现新文章时:自动下载 ⚙」),**让状态可见,而不是让人回忆几天前设了什么**。
- 顺带修掉一个既有缺陷:`lastCheckedAt` 此前只在一条分支写,自动下载模式与「无新文章」永远不记,于是页面左边显示「尚未检查」、右边同时显示检查结果。

**整类文章从来没被抓到过(R4)**

按公众号下载时「视频那篇被跳过」、「取不到最新文章(只到 7-17)」——两个现象**同一个根因:用错了列表接口**。

| 接口 | 总数 | 最新一篇 | 返回的类型 |
|---|---|---|---|
| 旧(图文素材) | 370 | 2026-07-17 | 只有普通图文 |
| 新(已发表) | **770** | **2026-07-25** | 图文 / 文字消息 / 视频消息 齐全 |

某号 7 月 17 日之后发的全是文字消息与视频消息,旧接口**一篇都看不见**——不是"跳过",是从未进入列表。实测抓最近 10 篇,**9 篇是旧接口看不见的**。

**连带一个没人报的问题更严重**:订阅检查走同一条链路,所以订阅号发的文字/视频消息**一直在漏检**,而检查记录显示「无新文章」,完全看不出来。修好后对同一个号回溯检查,补回 6 篇。

**解析改为按消息类型分发**,不再靠猜。旧实现是一串启发式(`#js_content` 非空就当正文用),它**对未知类型永远不报错**——视频消息页的 `#js_content` 是个分享提示壳,于是 21.8 万字符的内联 JavaScript 被当正文写进 content.md,一路绿灯。现在不认识的类型走兜底**但会在 `warnings` 里说出来**,新类型第一时间暴露而不是烂在文件里。

**跨 URL 形态的去重**:两个接口对同一篇文章给的 URL 形态不同(短链 vs 长链),导致已下载过的文章被重下。现在用微信自己的文章主键判重,并让老库里的旧格式 id 与新格式认作同一篇——**不需要迁移文库**。

**超时按资源体量分档**:此前只有视频按体积算,页面和图片共用固定 20 秒——而视频消息页实测 2.4MB,20 秒等于要求跑满 120KB/s,慢一点整篇失败。现在页面 60 秒、图片 30 秒(**刻意不放宽**:一篇的图是串行下的,单张放太松会让整篇卡很久)、视频按体积。

## 新增

**含视频的文章能下了(R2)**

- **视频是内容,不是格式**——文章带视频就一并下载,和图片一样,不需要在下载格式里勾选。单个视频可达上百 MB(实测 1572×1080 一档 **133MB**),批量抓取想省流量可在设置里关掉「文中视频」,或 CLI 加 `--no-video`。
- 落在 `videos/video-N.mp4`,**自动取最高清档**(按分辨率择优;`format_id` 数值与画质无关,数值最大的那档其实是 480×328)。
- `md` 给可点链接、`html` 给可播 `<video>`——**阅读器里直接就能播**。
- 不下载时正文仍注明「本文含 N 个视频(未下载)」,**不静默丢弃**;下载失败会写进正文并出现在 `warnings` 里。
- 文库对含视频、以及非普通图文的文章标出标识。

**更新检查 + 按渠道引导升级(R3)**

- 启动后延迟几秒静默检查,**有新版只在「设置」上点一个小圆点**——不弹窗、不打断。新版本可用不是紧急事。
- 设置页「检查更新」三态明确:检查中 / 已是最新 vX.Y.Z / 发现新版(展开版本号、发布时间与发布说明)。
- **按你的安装方式给不同动作**:brew 装的给一条可一键复制的完整命令(含 `brew update` 与 `xattr -cr` 两个必要步骤);手动装的按当前架构下载安装包并打开,附覆盖后的收尾提示。
- 「启动时检查更新」可关,每天最多查一次;**只向 GitHub 请求版本信息,不上传任何数据**。
- CLI:`wx-kit update --check` 给出 `channel` 与 `upgradeCommand`;查询失败明确报错(退出码 1),**agent 不会把失败误读成「已是最新」**。`wx-kit version` 仍不联网。

## 说明:不做静默自动升级

mac 的包是 adhoc 签名,Squirrel 的签名校验必然失败;而 brew 是本项目的必做分发渠道,应用自己替换二进制会让 brew 的版本账本对不上。所以本版做的是「让你知道有新版 + 明确告诉你怎么升」,不是偷偷替换。详细理由见 `docs/PRD-v0.8.2.md` R3。
