# v0.11.3 · 打包环境墨问修复 + 统一诊断日志

发布日期：2026-09-19 · 可靠性版本 · 需求/验收 `docs/PRD-v0.11.3.md`

## 修复

### 墨问功能在打包安装环境不可用（BAD_OUTPUT 三连修）

v0.11.2 及之前：从 dmg 安装的 wx-kit 里，墨问订阅「检查更新」与发现层对部分 mocli
安装形态恒报 `墨问请求失败（BAD_OUTPUT）：mocli 输出不是合法 JSON`，而开发模式
（`npm run dev`）一切正常。本版三处修复：

- **探测链真实工厂漏传环境变量**（根因）：mocli 定位链的「常见安装位 + nvm 扫描」
  步骤因 `HOME` 未传入而在生产环境整体跳过，永远落到 login shell 兜底——当兜底
  拿到的是用户手工建的符号链接（如 `~/bin/mocli`，所在目录没有 node）时，mocli 的
  `#!/usr/bin/env node` shebang 解析失败、输出为空，即 BAD_OUTPUT。现工厂透传
  `HOME/SHELL`（单测钉死契约）。
- **失败消息带真实原因**：BAD_OUTPUT 文案追加 stderr 首行摘要——此前猜「版本过旧」
  把排障方向带偏，现在 `env: node: No such file or directory` 这类线索直接可见。
- **PATH 防线前移**：启动期把常见工具链 bin 目录（nvm 最新版 / volta / asdf /
  npm-global / `~/bin` / homebrew 双前缀，存在才加，纯文件系统探测）预置进 PATH，
  `env node` 的可达性不再依赖「精确探测到 mocli」——探测链单环失灵不再致命。
  附带修复：未订阅任何墨问作者的机器，调度器每分钟不再空跑一次 mocli 探测
  （未装 mocli 时该探测以 spawn 登录 shell 告终）。

**用户视角**：mocli 装在 nvm / homebrew / 自定义链接的用户，从 Dock 或 Finder 启动
wx-kit（不加载 `~/.zshrc` 的最小 PATH 环境）墨问功能开箱即用；纯微信用户零感知、
零开销。

## 新增

### 统一诊断日志（M66）

运行日志自动记录启动环境与对外调用的关键事实，落
`~/Library/Application Support/wx-kit/logs/main.log`（Windows 在对应 userData 目录）：

- **默认常开** info 级，JSON 行格式，5MB×3 自动滚动，不清理也不膨胀；**无远程上报**；
- **敏感信息自动打码**：cookie / API Key / 签名参数等一律显示为 `«redacted:N»`——
  日志可以放心外发；
- 记录内容：每次启动的环境快照（版本、平台、**PATH/HOME/SHELL**——环境类问题的
  直接线索）、每次 mocli 调用（命令、退出码、耗时、输出首行摘要）、每次微信/微信读书
  请求（端点、耗时、错误）、每篇文章下载结果（成败与耗时）；
- **设置页新增「诊断」区**：一键打开日志文件夹（Finder 选中 main.log）。报障时把
  main.log 发给帮你排障的人，替代口头描述「报错了」。

背景：此前 wx-kit 没有统一日志——打包 GUI 的 console 输出用户看不到，两起 mocli
事故的关键线索（子进程 stderr）随进程消失，排障靠猜。本版起线索永远在场。
