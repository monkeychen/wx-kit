# v0.10.0 发布说明

**同一种能力，换一条活路。**

在 v0.9.0 退场后，我们找到了全新路线：通过**微信读书（WeRead）移动端接口**，全面复活公众号的按号下载与增量订阅功能。

### 核心特性复活
*   **按公众号批量下载**：输入文章链接自动识别公众号，获取该号的增量文章列表并批量下载。
*   **公众号订阅闭环**：添加订阅、定期自动检查（可设置时间/频率），发现新文章自动下载。
*   **命令行完全复原**：`search`、`crawl`、`login`、`subscription`、`auth-status`、`session` 等 CLI 接口全部恢复可用。
*   **纯 HTTP 极速扫码登录**：告别笨重的弹出窗口，直接在应用内（或 CLI 终端）渲染微信读书登录二维码，秒级响应，凭据保存在本地，自动过期续期。

### 数据扩展与能力降级
*   **[新增] 阅读数与点赞数**：得益于微信读书后端的特性，导出的文章 `meta.json` 及 `digest` 清单中现在将包含 `readNum` 和 `likeNum`，这是过往 MP 后台时代无法获取的增强数据！
*   **[降级] 无法搜索历史全量文章**：微信读书移动端接口（因强风控）无法继续使用，当前降级为 Web 端 `/api/mp/cover` 接口，仅能获取公众号的**最新一篇文章**。这意味着 `crawl` 历史回补名存实亡，但日常**增量订阅**依然完全可用（只要检查间隔小于公众号发文频率）。
*   **[降级] 取消按名字搜号**：由于新接口不支持名称搜索，添加订阅和识别账号统一改为“**粘贴该号的任意一篇文章链接**”。

### 底层增强
*   **双路请求网关与独立设备指纹**：微信读书流量拥有独立的速率控制档位与墨水屏设备请求头，与普通文章的 Chromium 页面抓取流量完全隔离。
*   **智能判重兜底**：即使是通过无 `hint` 的短链下载的文章，也会在抓取 HTML 后自动提取真实 `mid_idx`，与已有文库数据完美合并，解决同文短链/长链的重复下载问题。
