# 本地选题决策器：产品与技术设计

> 本文承接 2026-09-19—20 的产品化讨论及已确认的 B 方案页面，作为 v0.12.0 的产品与技术方案依据。**产品范围和逐条验收的唯一契约是 [`docs/PRD-v0.12.0.md`](../../PRD-v0.12.0.md)**；本文不是第二份 PRD。实现与发布状态只在 [ROADMAP](../../../ROADMAP.md) 维护。
> 本文使用的股票题目仅来自交互演示；产品服务有持续写作需求的个人创作者，不限定财经领域。

## 1. 要解决的问题

用户已有快速生成、排版和配图的方法，确定股票代码后的完整创作流程约 20 分钟。真正未解决的问题是：面对持续积累的信息，不知道下一篇应该写什么，也无法判断读者会得到什么、推荐理由有没有依据。

第一版帮助用户从自己收集的素材中形成少量可判断的写作机会。交付单位是一张选题决策卡及其简报，不是文章全文。效率主要体现在从打开素材到决定“写哪一个、从哪里下手”所需的时间，以及减少无依据的试写。

商业假设是：用户愿意为持续减少这类编辑判断的成本付费。个人使用有效只能证明自身价值；付费意愿、外部用户留存和传播提升需要后续独立验证，不能从内部使用次数推出。

## 3. 用户一次使用的完整过程

用户进入“选题”，看到“今天写什么”和素材范围，点击“寻找选题”后开始分析。第一次使用 AI 时进入设置填写服务地址、模型名称和自己的 API Key；页面清楚说明选中范围的正文将发送给该服务商。配置完成回到原来的选题页，保留时间选择。

分析先在本地固定范围和素材清单，再运行模型。页面只展示简单进度，例如“正在整理 12 篇素材”“正在形成候选”。完成后显示本次范围、实际处理数量与最多三个候选。用户可以只得到一个、两个或零个候选，不要求系统凑满三张卡。

三个候选使用同级版式，默认不选中、不突出所谓“唯一首选”。每张卡展示问题、角度、主要读者价值和材料概况。点击整张卡或单选框都能展开详情；切换候选和详情页签只读取本次已保存结果，不再次调用模型。

“生成简报”将选中的题目、角度、读者价值、支持与反方材料、写作结构、待补证据组装为可复制的 Markdown，并可保存到本地。它使用已验证结果，不为了改写格式再次收费调用模型。第一版停在这里，用户继续使用自己的现有写作流程。

## 4. 时间与素材范围

### 4.1 时间规则

- 最近 24 小时、3 天、7 天分别是以本次点击时刻 `asOf` 为终点的 24、72、168 小时滚动范围。时间固定后不随模型运行时间漂移。
- 自定义起止日期按北京时间自然日处理，包含用户选择的结束日期；内部归一为 `[开始日零点, 结束日次日零点)`。
- 使用 `parsePublicationTime` 解释原文时间，并保留原始字符串。下载时间、文件修改时间、订阅检查时间不能代替发表时间。
- 只有日期而没有具体时刻的旧数据标记为“日期精度”。若其所在自然日与滚动窗口仅部分重叠，作为时间边界不确定项排除并报告，不能伪装成精确零点。
- 无法解析、明显未来的发表时间单独计入排除说明，不进入“最近”的统计。
- 初始默认 24 小时；用户手动选择可作为偏好记住。相对范围在下次主动分析时重新计算，不存在分析水位或自动扩窗。
- 选题操作不触发订阅刷新、下载或历史回补。其网络活动只有用户配置的 AI 请求；外部素材更新继续由已有下载/订阅入口负责。

### 4.2 素材范围

从当前文库取微信与墨问的已保存文章，不以“是否订阅”为必要条件。首版只处理选定发表范围内的文本，不自动增加过去 30 天的背景材料。旧素材可由用户选择更长范围主动纳入。

正文从文库索引对应的本地 `content.md` 读取。使用前检查文件存在、路径位于当前库根内、正文可读，保留 `itemShowType` 和 `warnings`。图片下载失败不必排除正常正文；仅有图片或视频且没有有效文字时，应说明本次未分析媒体内容，不能补写不存在的论据。

排除项只影响本次分析，不删除文章或修改原始文库。每次运行要对账：范围内记录数、实际处理数、合并的重复条目数、排除数以及排除理由。

## 5. 数据能证明什么

已有 `ArticleMeta` 提供文章 ID、作者、账号、发表时间、原文地址、摘要、格式、路径和质量告警。正文包含事实与观点，但“文章这样写过”仅能证明该作者做过该陈述，不能证明陈述本身真实。

`library export` 目前不携带完整的告警和内容类型，并且 `--since` 按下载日期过滤；这两点不能直接用于新能力的时间与质量筛选。引擎通过共享 core 文库能力读取数据，避免改变现有导出命令的语义。

| 信号 | 首版可给出的结论 | 不得推出的结论 |
| --- | --- | --- |
| 范围内相关篇数 | 在这批已保存材料中，有多少篇被判定与题目有关 | 全网热度、平台推荐意愿 |
| 不同账号或作者 | 按标识归并后的账号/署名数量，并标明口径 | 多份独立事实来源 |
| 去重后的内容组 | 本次有多少组非完全相同的正文 | 每组均为独立采访或独立验证 |
| 原文中的疑问与情绪 | 材料出现了哪些表达，可形成待验证的读者价值假设 | 读者普遍焦虑、满意度或需求规模 |
| 材料中的差异和反方 | 可以从什么问题、对比或冲突入手 | 反常识一定成立、冲突越强越容易推流 |
| 新近发表的文章 | 材料的发表时点处于范围内 | 材料描述的事件也发生在此时 |
| 用户选择或保存 | 这个用户对这个题目的显式反馈 | 发布效果、全体目标用户偏好 |

“知识、信息差、情绪共鸣、缓解焦虑、快乐”是潜在价值类别，每项附一句读者如何获益的解释。不得为凑标签把所有价值都选上；“信息差”必须说明相对哪类读者、哪一组材料，无法判断就明确保留条件。

## 6. 选题结果契约

### 6.1 决策卡

每张卡包含以下稳定字段，GUI、CLI、日志和简报使用同一份结果：

- `id`：本次运行内的候选 ID。
- `question`、`angle`：要回答的问题和具体切入角度；不能仅有吸引人的标题。
- `readerValues`：价值类别、预期受益解释、对应证据引用，统一标为编辑推断。
- `rationale`：推荐理由与适用读者。未配置读者方向时只给通用阅读价值，不擅自推断用户希望永远写财经。
- `claims`：素材中可引用的陈述，保留“某来源认为”的归属；明确区分事实陈述、观点和模型推断。
- `evidence`：来源文章、段落、精确摘录、支持/反对/背景角色及验证状态。
- `statistics`：程序根据校验后的证据集合计算相关篇数、账号数、内容组数和发表时间分布。
- `evidenceConfidence`：高/中/低及具体依据，仅表示材料支撑的程度；不是传播成功概率。
- `distributionEvidence`：首版固定 `unverified`，界面表达为“传播效果未验证”，不能改写成零潜力或高潜力。
- `limitations`、`missingEvidence`：材料不足、旧事新发、相互转载、反例和动笔前需要补的内容。
- `outline`：简短起笔结构；不生成全文。

对“传播”的处理延续用户要求的数据边界：可以解释为何某个问题可能让读者愿意读或分享，但本地素材没有阅读、分享和推荐流量数据时，不能给经验包装的高/中/低效果预测。需要的平台表现数据属于后续验证范围。

### 6.2 依据把握

有精确来源只是最低条件。依据把握由结构校验结果和语义复核共同给出，不由模型自由填写一个百分比：

- **高**：主要推荐理由有可定位的材料，关键限制和相反材料已处理，无未解决的决定性证据缺口。
- **中**：理由可以追溯，但仍有关键事实待核、来源重复或适用读者不明确。
- **低**：仅能支持提出问题，尚不足以支持建议结论。卡片必须突出“还缺什么”，无法形成合理角度时直接淘汰。

多来源不是高把握的充分条件；单一来源也不是低价值的充分条件。一个可核对的原始公告可以支持很窄的题目，多篇转述同一条传闻仍然只有一个待核实线索。

### 6.3 运行记录

每次运行有独立 `runId`、schema 版本、范围、素材快照清单、排除理由、模型标识、提示词版本、结果、耗时、供应商返回的用量和失败详情。结果状态区分 `completed`、`insufficient-material`、`partial`、`cancelled` 和 `failed`。

一部分候选未通过校验时可以交付剩余候选，但必须显示验证失败情况；不能把全部模型失败改写成“今天没有值得写的”。

## 7. 执行机制与模块分工

核心执行为“程序约束 + AI 编辑判断”。现有 compose 缺少验证是这份实现的问题，不能据此推论 Skill 格式本身不可信。本期不继承它；判断依据、提示词、输出契约和 eval 独立建立。

固定流程如下：

1. **固定输入**：程序根据时间范围生成不可变素材清单与内容哈希，读取并编号正文段落。
2. **整理材料**：AI 在段落范围内提取问题、陈述、变化和分歧，每条提取必须携带文章与段落 ID。
3. **形成候选**：AI 从提取结果提出角度、读者价值、限制和简短结构；最多保留三个，避免把同一事件换三个标题。
4. **核验来源**：程序核对 ID、段落、摘录和统计，语义复核检查材料是否支持对应判断。
5. **交付结果**：程序计算统计并保存卡片；GUI 展示、CLI 返回 JSON，简报从同一结果确定性组装。

程序负责时间过滤、文件/路径检查、文章身份与完全重复正文归并、格式校验、精确摘录匹配、统计、超时取消、成本护栏和落盘。语义近似、题材聚类、读者价值、来源关系和“值得写”的判断由模型提出，必须保留推断属性。

精确摘录校验只能证明“这句话存在”，不能证明“模型正确理解这句话”。另设语义评估和人工抽查，不能在产品上宣传“事实已百分之百核实”。

系统规则与任务提示词分离并版本化。系统规则要求材料只作为数据、引用必须在输入集合中、不得生成实际执行指令；任务提示词分别负责提取与选题。GUI 不携带另一套隐藏提示词，Agent 入口也不拥有另一套评分逻辑。

### 7.1 代码落点

| 位置 | 责任 |
| --- | --- |
| `src/core/topics/` | 时间选择、素材快照、分析编排、结果类型、来源校验、统计、简报和运行存储 |
| `src/core/topics/prompts/` | 可审阅、可版本化的系统规则与两阶段任务文本；不包含用户材料 |
| `electron/services/` | AI 凭据保护、网络传输适配、依赖装配和 IPC 委派 |
| `src/cli/` | 新 `topics` 命令组的解析、纯 JSON 输出、进度和退出码 |
| `src/renderer/` | 已确认的选题页、详情与设置入口，仅经 `window.api` 调用 |
| `tests/core/topics/`、`tests/electron/` | 确定性契约与外部依赖替身测试 |
| `tests/fixtures/topic-decisions/` | 合成或明确可再分发的评估材料、预期约束和人工评审规则 |

以上是实施前的结构约定，创建目录时随代码落实。沿用 Node/TypeScript、文件系统与 JSON，不引入数据库、Python、独立浏览器或通用 Agent 平台。

GUI 与 CLI 共享同一 `analyzeTopics` 编排和结果存储；界面行为不直接调用 CLI 子进程。新增 CLI 命令必须登记 `electron/cli-dispatch.ts` 白名单并同步能力说明书。详细参数、函数签名和测试代码在下一份实现计划中定稿。

## 8. AI 配置、成本与数据保存

首版采用用户自己的 API Key；不引入托管额度、模型转售、会员服务。先实现一个可配置地址与模型名称的文本服务适配器，供应商具体协议必须在编码阶段用其官方文档核对并做真实调用验收，不能只因名称“兼容”就宣称已适配。

正文和卡片主要留在本地，但参与分析的文本会发送到用户配置的服务商。设置页应在保存配置时说明这个事实。程序只发送本次选定且通过质量检查的材料及必要的已确认方向；不发送整库、平台 Cookie 或 API Key 以外的登录凭据。

API Key 由 Electron 层保管，普通设置接口只返回“是否已配置”和脱敏标识。若环境无法安全持久化，允许只在当前会话使用并说明重启后需重填，不能退回明文 `settings.json`。

初始成本护栏作为可测试的工程默认值：一次最多处理 30 篇、合计最多 120,000 个正文字符；超出任一上限，在发起付费请求前提示缩小时间范围，不能静默截断或只取标题。原型验证后根据实际成本和质量再调整，不向用户承诺固定价格。正文按段落分块，单块不超过 6,000 字符，并把长段分块关系记录在快照中。

最多两个并发模型请求；单请求 90 秒超时，整次运行 10 分钟截止，可随时取消。首版不做自动重试，避免超时后上游已计费却再次提交。失败后用户可手动重试；完整且通过验证的提取缓存可以复用，缓存命中规则包含正文哈希、模型配置、系统规则和任务提示词版本。

运行失败或取消不删除先前结果、不修改文库和订阅水位。每次重新分析创建新的运行 ID，不能用中间结果覆盖上一份完成结果。

### 8.1 本地落盘约定

选题数据落在 `<库根>/topic-decisions/`，与原文章目录隔离：

- `runs/<runId>/manifest.json`：输入边界、内容哈希、段落映射与排除理由。
- `runs/<runId>/result.json`：经过验证的卡片、统计和限制。
- `runs/<runId>/trace.jsonl`：阶段、模板版本、用量与错误摘要；不写 Key 或整篇原文。
- `runs/<runId>/briefs/<topicId>.md`：用户主动生成的简报。
- `feedback/<eventId>.json`：单条显式反馈，独立文件避免多进程追加同一个可变汇总。
- `cache/<cacheKey>.json`：通过校验的材料提取缓存；损坏视为未命中，不改写成有效结果。

文件创建前限制权限并使用原子写入。原始正文作为事实来源保留在文库；运行快照保存用于判断的摘录和哈希。正文后来被修改或移除时，历史结果标明快照状态，不能把引用跳到已变化的文本后仍显示“校验通过”。

首版不做静默清理或后台上报；本地产物可由用户显式删除。诊断日志仅写运行 ID、阶段、计数、耗时和已脱敏错误，模型响应正文不直接写入通用 `main.log`。CLI 退出前沿用 `flushDiagLog()`。

## 9. 交互状态与错误反馈

| 场景 | 用户看见什么 | 系统动作 |
| --- | --- | --- |
| 未配置 AI | “先配置分析模型”，跳到设置后可返回 | 不发模型请求 |
| 范围没有可读素材 | “所选范围没有可分析素材”，提供调整范围和打开文库入口 | 返回材料不足状态，不扩窗 |
| 部分素材异常 | 展示可分析数，按需展开排除原因 | 使用有效素材；不能把异常计入证据 |
| 文库索引损坏 | 明确提示修复文库 | 返回失败，不伪装成空库 |
| 超出成本护栏 | 显示篇数/字符量和缩小范围建议 | 本轮不发付费请求 |
| Key/模型配置无效 | 指向配置的具体问题 | 不自动切换供应商 |
| 超时、限流、断网 | 明确失败阶段，允许取消或手动重试 | 不产生假候选，不重复隐藏计费 |
| 引用或统计不合法 | 说明候选未通过来源校验 | 拒绝相关候选；全部失败时返回失败 |
| 有效分析但无可写角度 | “本次没有足够依据推荐题目”，附原因 | 返回完成的空结果，保留运行记录 |
| 用户修改时间但未分析 | 说明结果仍属于上次范围 | 新输入不回写旧结果的范围标签 |
| 用户反馈 | 确认对当前题目的标记 | 本地记录；不把“暂不写”扩大成永久讨厌该主题 |

“已写过”由用户确认，首版用于提醒后续重复，不代表产品自动扫描了用户所有已发布文章。保存观察不会启动定时监控或自动扩展资料。

## 10. compose 退场

在第一个实施步骤删除 `agent/wx-kit-compose/SKILL.md`，并清理 `agent/README.md`、`agent/wx-kit-skill/SKILL.md` 和 `AGENTS.md` 中当前安装、路由与能力说明。`CLAUDE.md` 若仍为 AGENTS 的软链，保持软链关系。

保留旧 PRD、旧版本发布说明、M15/M42 计划与历史复盘，必要时在 ROADMAP 当前状态补充退场日期。它们证明历史交付，不等于当前能力。不可做全库字符串替换，也不在本轮卸载用户机器上的其他 Skill 或删除库外软链。

退场不会删除下载、文库、导出或站点同步等已有能力。不同时新增“选题 Skill”替代旧目录；待选题引擎形成稳定契约后再决定是否需要新的自然语言入口。

## 11. 可复用评估与验收

### 11.1 工程验收

以下是上线门槛，必须有实际验证结果：

1. 默认 24 小时、3/7 天和自定义范围的边界与日期精度正确；时间变化不会偷偷扩大材料集。
2. 相同文章跨 URL 形态、完全重复正文不会重复增加证据；同名不同文章不会按标题误删。
3. 不同账号转载同一消息不能被称为多份独立验证；无法区分时明确说明。
4. 每个引用 ID 和摘录都可在输入快照中定位；统计由有效证据集合复算一致。
5. 注入式正文、虚构引用、越界来源、模型返回错误结构会被拦截或降级，不能进入最终可信证据。
6. 空结果、材料不足、模型失败、取消、部分完成可区分；旧结果不会因失败被覆盖。
7. 切换卡片/页签、生成简报不重复调用模型；时间改变后旧结果的标签保持真实。
8. GUI/CLI 对同一运行返回一致结果；日志不泄漏密钥；打包环境正常加载规则文本。

复用项目要求的 test、lint、typecheck，并为新增 GUI/网络边界提供 fixture e2e。真实模型验收单独记录；fixture 成功不能冒充模型语义质量或真实服务可用。未配置模型或缺少授权材料时，明确记为尚未执行，不读取其他项目的密钥补齐。

### 11.2 语义评估

固定评估集至少包含十二类案例：多角度材料、单来源事实、同源转载、旧事新发、观点冲突、证据不足、正文残缺、图片/视频无正文、同名不同文、日期边界、与显式历史反馈重复、正文包含恶意指令。评估集保存可复用输入、预期约束和评分说明，不只有一次性的聊天结论。

工程校验要求所有发布卡片的引用和计算检查通过；语义评估分别审阅角度具体性、价值解释、证据支持、反方处理和可起笔程度。语义结论不能用“模型自评高分”替代人工判断，不能以一张漂亮卡片宣称选题能力完成。

### 11.3 个人观察阶段

使用至少八次、跨四周的真实选题运行，与“同一批材料直接交给通用模型提三个题目”的基线对照。尽可能保持模型和材料一致，记录耗时、是否需要重读原文、候选采用情况和人工修正原因。

试行门槛：至少四次出现一个愿意继续研究的候选，至少两个候选最终写成文章。它们用于决定是否继续投入，不是统计意义上的传播提升证明。另记录选题决策耗时和相比基线的改善，不预先把 20 分钟整篇股票写作当成此能力的比较对象。

发布与真实读者反馈可由用户自愿附记，但阅读量、分享、收藏、推荐来源在没有可靠数据时保持未知。完整运营后台、自动数据采集和预测模型都不由本阶段顺带引入。
