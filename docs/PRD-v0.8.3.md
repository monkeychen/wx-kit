## 2. 需求清单

### R1 · 列表接口应过滤读者不可访问的文章(2026-07-27 安哥)

**原始现象**:用「按公众号下载」抓「猫笔刀」最近 3 篇,**3 篇里 2 篇失败**,看着像是违规内容。安哥问:查询文章列表的接口是否该过滤?

**核实结论(2026-07-27 真实复现 + 抓页面 + 查接口字段)**:该过滤,而且**列表接口早就给了标记,是我们没读**。

复现结果:`succeeded: 1, failed: 2`,两条失败都是
`invalid or unavailable article (no title parsed)` —— 这是我们对「已删除文章返回 HTTP 200 错误页」的兜底判定,笼统且没说清原因。

抓那两篇的页面:标题是**「此内容发送失败无法查看」**,正文「此内容因涉嫌违…」。

查列表接口对这几篇返回的状态字段:

| 文章 | `checking` | `is_deleted` | `ban_flag` | 下载结果 |
|---|---|---|---|---|
| 试试看(07-26 14:46) | 0 | false | 0 | ✅ 成功 |
| 2000亿红包(07-26 14:37) | **1** | false | 0 | ❌ no title parsed |
| 2000亿红包(07-26 14:26) | **1** | false | 0 | ❌ no title parsed |
| 忘不掉的2块钱(07-25) | 0 | false | 0 | ✅ 成功 |

**`checking: 1` 就是信号**(公众号后台的「发送失败 / 审核中」状态)。M36 换接口时只过滤了 `is_deleted`,
把同一批字段里的 `checking` 漏了。同批还有个 `ban_flag`(本例全为 0,**无样本**,但顾名思义是封禁标记)。

**性质**:这不是「加一个过滤功能」,是**修掉一处漏读**——这些文章读者根本打不开,
留在列表里只会产生**必然失败**的下载,还把失败原因说成含糊的「no title parsed」。

**选型(2026-07-27 安哥定)**:

- **过滤掉,并往后补足**:`--count 3` 的语义是「给我 3 篇真能下的」,跳过不可访问的继续往前翻直到凑够。
  代价是可能多翻一页(多一次请求,频控上可控)。
- **但不能静默**:结果里要说清「跳过 N 篇不可访问(审核未通过/已下架)」——延续 v0.8.2 的主题,
  过滤本身合理,静默过滤则会让用户奇怪「我明明看到有 3 篇」。

**细化方案(次要决策为 agent 按项目惯例所定,安哥可推翻)**:

- **`fetchPage`(`src/core/mp-client.ts`)**:过滤条件从 `is_deleted` 扩到
  「`is_deleted` 或 `checking` 非 0 或 `ban_flag` 非 0」,抽成一个具名判定(如 `isReaderVisible(a)`)并注释清楚每个字段的含义与出处。
  被过滤的条目**计数并带出**(不能只是消失),供上层汇总。
- **补足语义**:`listArticles` 的 count 模式按「可下条数」计,过滤掉的不占额度;
  翻页终止条件仍受 `total`/空页保护,避免为凑数无限翻。
- **上报**:`CrawlSummary` 增「跳过不可访问 N 篇」;GUI 批量结果区与 CLI JSON 都要显示。
  **文案要说人话**——「审核未通过或已下架,读者不可见」,而不是回显 `checking=1`。
- **订阅检查同链路受益**:`checking:1` 的文章不再被当成「新文章」反复尝试下载并失败
  (此前每次检查都会撞一次)。水位推进逻辑要复核:被过滤的文章**不应阻断水位**,否则会卡住。
- **兜底不动**:`download-article.ts` 里「解析后标题为空即视为无效文章」的判定保留
  —— 单篇 URL 下载(用户手动粘贴一个违规链接)没有列表字段可依据,仍需它兜底;
  但**失败话术可以更准**:识别出错误页特征(如「此内容发送失败无法查看」)时给具体原因。

**验收(草)**:

- [ ] 抓「猫笔刀」最近 3 篇:拿到 **3 篇可下的**(跳过那两篇 `checking:1`,继续往前补),不再 `failed: 2`。
- [ ] 结果里明确报告跳过了几篇及原因(GUI 与 CLI 一致),不静默。
- [ ] `is_deleted` / `checking` / `ban_flag` 三种状态都过滤;用 fixture 钉死(含各字段的正负样本)。
- [ ] 日期范围模式(`--from/--to`)同样过滤,且不因过滤而错判「已翻到窗口外」。
- [ ] 订阅检查不再把不可访问的文章当新文章;**水位不被卡住**(被过滤的文章不阻断水位推进)。
- [ ] 单篇 URL 下载违规链接时,失败原因比「no title parsed」更准确。
- [ ] 既有链路不回归(单测 + e2e 全绿),真实抓取端到端验证。

**待议**:`checking: 1` 是否为**临时**状态(审核中→可能通过)?本例两篇是同一标题的两次尝试,
均被拦。若是临时的,过滤后下次检查会自然重新出现,无需额外处理;
若要区分「审核中」与「审核不通过」,当前字段不足以判断,**不做猜测**。
