# wx-kit v0.10.6 产品需求文档（迭代 PRD）

> R1 对应 M58（2026-09-09 安哥提出并确认设计）。当前进度见 `ROADMAP.md`，验收以本文第 6 节为准。

## 1. 一句话定义

**每一轮订阅检查涉及了哪些文章、各自什么状态，就在那一行里摆出来；没下载的当场就能下。**

## 2. 背景与已确认交互（安哥拍板）

- 现状：行内展开只显示「待处理列表」（`newRefs`），自动下载完成后列表清空——**下载了什么、
  结果如何，行内看不见**；提示策略的展开面板只有勾选批量，没有单篇粒度的动作。
- 已确认：① 点击**已下载**文章标题 → **直接打开阅读器**（路由 `/reader/:id`，不经文库页）；
  ② 「仅提示」策略保留**勾选批量**，同时每篇未下载文章提供**「下载」按钮**（并存）；
  ③ 未下载/失败的文章点标题仍开浏览器原文（现状行为）。

## 3. 需求清单

### R1 · 订阅行内「本轮检查文章列表」（检查后显示、持久、可操作）

**用户目标**：检查更新后，每个公众号行内展开即见**本轮检查涉及的文章**（标题 + 状态）；
列表保留到该号下一次检查为止（含应用重启）；未下载的可以逐篇下载并就地看到结果。

**数据层**：

- `DownloadItemLog.status` 扩展第 5 态 **`pending`**（未下载，提示策略检查时的初始态）；
  每篇增加 `articleId?`（文库条目 id——下载成功或判定「文库已有」时回填，阅读器跳转用）
  与 `url?`（原文链接）。
- 检查记录 `downloadDetail` 扩展为**本轮检查的每个号都落条目**：有新文章的号落逐篇明细
  （提示策略全 `pending`、自动下载策略落结果态），无新文章的号落**空 `items`**（显式表达
  「查过、无新」）。单行日志不进明细的纪律不变；`recentLog`/弹窗等既有消费方按 `items`
  过滤即可兼容。
- 下载动作完成后（单篇或批量）**更新最近一条检查记录**中该号对应文章的状态（`pending →
  downloaded/failed/...`）并回填 `articleId`——最新一条记录是「本轮状态面板」，历史条目不动。
  简化边界：若下载前又跑了新一轮检查（目标文章已不在最新记录里），不回填，等下次检查刷新。

**行为层**：

- 每号的行内列表数据源 = **检查日志中最近一条含该号条目的记录**的 `items`——行内单查号 A
  不会清掉号 B 上轮的列表；「检查全部」后所有号按本轮真相刷新（无新文章的号列表清空）。
- 单篇下载复用现有 `subscriptionsDownloadNew(fakeid, ids)` 通道（全局网关串行、进度广播、
  完成后 newRefs 清理均继承），完成后行内状态就地更新。
- 已下载/文库已有的文章点标题 → 直接打开阅读器；未下载/失败/不可访问点标题 → 浏览器原文。

**UI 层**（行内展开面板重构）：

- 每篇一行：勾选框（保留批量）+ 标题 + 状态 Tag + `pending` 态的「下载」按钮；
  Tag 五态：已下载（绿）/ 文库已有（青）/ 下载失败（红，悬停看原因）/ 不可访问（灰）/
  未下载（默认）。
- 「下载全部待处理」全局按钮、勾选批量下载、忽略——全部保留不动。

## 4. 交互约定

- 行内摘要（M56）继续显示；列表是摘要的展开，两者同源（同一份检查记录）。
- 下载中的行：该号「下载」按钮与勾选禁用（沿用 busy 语义）；进度显示沿用现有行内进度条。
- 空列表不占位：该号最近一次检查无新文章时，展开区不渲染（与现状一致）。

## 5. 非目标

- 不改 CLI `check-now`/`list` 的输出结构（GUI 行内需求；`recentLog` 新增空 `items` 条目由
  skill 文档说明兼容）。
- 不做列表内文章的「忽略」单篇按钮（忽略仍走勾选批量）。
- 不改自动下载策略、检查调度、网关与串行语义。
