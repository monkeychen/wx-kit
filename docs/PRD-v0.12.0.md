# wx-kit v0.12.0 产品需求文档（迭代 PRD）

> 状态：**开发完成，尚未发布**（2026-09-21）。
> 本文是 M67–M70 的产品范围与验收契约；方案依据见
> `docs/superpowers/specs/2026-09-20-topic-decisions-design.md`，实现步骤见对应 `docs/plans/`。
> 当前发布版仍为 v0.11.3，根包版本在正式发版前不提前修改。

## 1. 一句话定义

**把本地文库变成一个可解释的选题工作台，帮助已有素材但不知道写什么的创作者，更快决定下一篇写什么、为什么值得写、从哪里下笔。**

## 2. 用户问题与成功标准

### 2.1 目标用户

持续写公众号、网站或其它图文内容的个人创作者，已经有收集素材和调用大模型的习惯，
但缺少稳定的选题判断过程。首版面向普通用户，不要求理解提示词、向量库或 Agent 编排。

### 2.2 核心问题

用户面对一批已收集的信息时，不知道：

- 哪个问题现在值得写；
- 读者可能获得知识、信息差、情绪共鸣、缓解焦虑或快乐中的哪些价值；
- 推荐理由依据了哪些本地材料；
- 哪些只是编辑推断，哪些事实仍需补充验证；
- 文章第一步可以从哪里下手。

### 2.3 首版闭环

本地文库 → 用户选择时间范围 → 最多三张可解释选题卡 → 用户主动选择 →
查看理由、材料与起笔结构 → 记录反馈或生成选题简报。

系统不替用户自动选题，不根据模型自评分承诺平台推流、阅读量或“爆款概率”。

### 2.4 成功标准

工程完成不等于产品有效。v0.12.0 的成功分两层：

1. **工程层**：同一份本地材料可经 GUI/CLI 得到可追溯、可复算、失败不伪装的候选；
   密钥和正文边界可核验。
2. **产品层**：在真实自有文库中，用户能从候选中找到至少一个愿意继续判断或动笔的题目，
   并认为它减少了“翻素材却不知道写什么”的时间。该层必须通过真实使用记录验证，不能由
   fixture、模型自评或测试数量代替。

## 3. 产品需求

### R1 · 用户控制素材范围

- 初始默认最近 24 小时，可选择最近 3 天、7 天或自定义开始/结束日期。
- 只按原文真实发表时间筛选，不用下载时间、目录名或订阅检查时间替代。
- 用户点击分析后，本轮时间边界固定；素材不足时如实提示，不自动扩展到更早范围。
- 只有日期、没有具体时刻的旧材料保留时间精度；与范围边界部分重叠时不猜测具体时刻。
- 单轮最多处理 30 篇有效文章和 120,000 个去重正文字符；超限要求用户缩小范围，不静默截断。

### R2 · 候选必须可解释、可追溯

- 单轮最多交付三张候选卡；允许合法返回零张。
- 每张卡包含：题目问题、写作角度、读者价值、推荐理由、材料依据、依据把握、限制、
  待补证据和起笔结构。
- 材料摘录必须能在本轮不可变快照的编号段落中逐字定位；匹配只证明摘录存在，
  不等于外部事实已经验证。
- 文章数、账号数、内容组数和发表日期由程序重算，模型不得直接提供最终统计。
- 完全相同的正文合并为一个内容组，但保留原文章身份；账号数量不得称为“独立事实来源”。
- 读者价值和推荐理由明确属于编辑推断；传播效果固定为“未验证”。
- 模型结构错误、坏引用和部分坏卡必须保留失败类型，不能伪装成“今天没有值得写的”。

### R3 · GUI 为主要普通用户入口

- 主导航新增“选题”，页面标题为“今天写什么”。
- 三张候选平等展示，分析完成后默认不选中任何一张，不用排序或视觉权重暗示“系统替你决定”。
- 用户点选候选后，同页按“为什么值得写 / 材料依据 / 怎么下笔”渐进展开详情。
- 材料页显示来源标题、账号、逐字摘录和 HTTPS 原文入口，并提示“摘录存在不等于事实已验证”。
- 分析中显示当前阶段并允许取消；材料不足、完成空结果、部分成功、取消和失败使用不同反馈。
- 未配置模型时给出“前往设置”的可行动入口，不发模型请求。

### R4 · CLI 为 agent 自动化入口

- `wx-kit topics analyze` 支持 `24h/3d/7d/custom`，stdout 保持单行 JSON，stderr 输出阶段进度。
- `wx-kit topics brief --run <runId> --topic <topicId>` 读取本地结果生成 Markdown，
  不再次调用模型。
- CLI 与 GUI 共享 `src/core/topics/` 的时间、快照、校验、统计、状态和简报逻辑，
  不维护第二套提示词或判断规则。
- CLI Key 只从 `WXKIT_AI_API_KEY` 读取，不提供 `--api-key`，避免进入 shell 历史。

### R5 · BYOK 与数据出机边界

- 首版只承诺 OpenAI Chat Completions 兼容协议，不承诺“兼容所有模型供应商”。
- GUI 在“设置 → 选题 AI”保存 base URL、model 和 Key；分析页与设置页都明确提示：
  所选文章正文会发送到用户配置的外部服务。
- base URL 和 model 可进入普通设置；Key 不得进入 `settings.json`、renderer 可读状态、
  stdout、result、trace 或诊断日志。
- 系统加密可用时，Key 用 Electron `safeStorage` 加密后独立以 0600 权限原子落盘；
  不可用时只保留当前进程内存并显示“仅本次会话，重启需重填”，不得降级明文。
- 本地 manifest 可在文库私有运行目录保存本轮正文快照；result/CLI 输出/简报只保留通过校验的
  必要证据摘录，不复制整篇正文；trace 与诊断日志不记录正文或模型请求体。
- 模型通道诊断只记录脱敏后的端点、模型、阶段、状态和耗时；自动重试为零，避免重复计费。

### R6 · 反馈与选题简报

- 用户可对选中候选记录“暂不写 / 保存观察 / 已经写过”。每次反馈独立落事件文件，
  不把一次“暂不写”升级成永久主题偏好。
- 用户可生成确定性的 Markdown 选题简报；生成后自动复制，并可在 Finder 中显示文件。
- 切换卡片、切换详情页签、反馈和生成简报均不得再次调用模型。
- 运行产物保存在 `<文库根>/topic-decisions/`；真实评估产物和用户文库不得提交仓库。

### R7 · 状态与失败语义

- `completed`：分析完成，允许零候选。
- `insufficient-material`：所选范围没有可分析文字材料。
- `partial`：至少一张候选有效，同时有提取项或候选未通过校验。
- `cancelled`：用户取消，不包装成请求失败或空结果。
- `failed`：供应商、校验或存储失败，保留结构化错误。
- 同一时刻只允许一个 GUI 分析；第二次请求引导用户等待或先取消当前分析。

## 3.5 非目标

- 不生成全文，不改写用户已有写作流程。
- 不做配图、微信公众号排版、多平台发布、引流交易、支付、会员或佣金结算。
- 不抓全网热点，不把本地素材数量称为全网热度。
- 不接平台阅读、点赞或推荐数据，不预测阅读量或推流概率。
- 不做后台监控、自动选题、自动扩窗或“自上次分析以来”的隐式水位。
- 不复活旧 `wx-kit-compose`，不为选题维护与 core 并行的另一套工作流。
- 不在 v0.12.0 同时解决商业化闭环；本版先验证选题效率是否真实存在。

## 4. 验收清单（逐条）

### 4.1 时间、快照与证据核心（M67–M68）

- [x] 24h/3d/7d/custom 按北京时间和真实发表时间筛选，覆盖跨年、闰日、边界毫秒、
  日期精度和非法输入。
- [x] 十二类合成评估材料覆盖同源转载、旧事新发、单来源事实、观点冲突、残缺正文、
  纯媒体、重复角度和材料内指令注入。
- [x] 快照做路径边界、正文质量、完全重复分组和 30 篇/12 万字符护栏。
- [x] 模型返回按 unknown 处理；段落、逐字摘录、证据引用、卡片数量和最终统计均经运行时校验。
- [x] manifest/result/trace/brief 私有落盘；失败状态互相区分。

### 4.2 CLI 与模型协议（M69）

- [x] `topics analyze/brief` 进入 CLI 白名单，不会误开 GUI 后挂起。
- [x] Chat Completions 本地 HTTP fixture 验证请求路径、Bearer、严格 JSON、usage、超时、取消和零重试。
- [x] CLI help 与 agent Skill 明确正文会发送外部服务，Key 仅从环境变量读取。
- [x] 测试 Key 不进入 stdout、result、trace 或诊断日志。

### 4.3 GUI、安全存储与完整闭环（M70）

- [x] 设置页支持保存/清除配置，并区分“已安全保存”和“仅本次会话”。
- [x] Key 加密文件不含明文、权限 0600；普通 settings 不含 Key；损坏密文给可行动错误；
  会话 Key 替换时删除旧密文，避免重启后复活旧 Key。
- [x] 选题页面支持四种范围、三卡平等、默认未选、详情三页签、取消和不同结果状态。
- [x] 反馈独立事件落盘；简报复制并提供显示文件；两者均不增加模型请求。
- [x] Electron fixture e2e 走真实 renderer → preload → IPC → core → 本地 HTTP 模型闭环，
  恰好两次模型请求；Key、Authorization 和整篇正文在普通设置/result/trace/main.log 中零命中。
- [x] 全量 93 个测试文件、902 个单测，lint 0 错误、TypeScript 检查和 Electron e2e 通过
  （2026-09-20）。
