# wx-kit v0.10.3 产品需求文档（迭代 PRD）

> R1–R2 对应 M57（2026-09-07 确认）。当前进度见 `ROADMAP.md`，验收以本文第 6 节为准。
> 本版是小版本：两个小修，无新能力面。

## 1. 一句话定义

**别让命令行入口悬空，别让筛选框显示一串 ID，别让识别按钮毫无声息。**

## 2. 背景与已排除需求

- **文章阅读数等计数（2026-09-07 spike 终局：不可行，勿再投入）**——安哥提出想获取文章
  「阅读数」等关键信息。三条通道逐一判死：微信原生阅读数由 `getappmsgext` 动态取、需手机
  微信客户端登录态，匿名请求为空（第三方 `wechatarticles` 即此路线：手机抓包 + key 短时效，
  与桌面产品不兼容且违背「不重新引入代理抓取」）；微信读书侧唯一活接口 cover 的完整 payload
  无任何计数字段，其余 review/article/info/book 接口全 404，「看过」数若存在也在已封禁的
  移动端接口体系里；第三方数据商需付费 token，超出产品定位。实证脚本留档
  `scripts/spike-weread-readcount.mjs`（结论已写入注释）。
- **公式保真**——v0.10.2 时定为「下一版首选项」，2026-09-07 安哥改定**继续推迟到下下版**。
- Windows CLI stdout 正解、CLI wrapper 之外的候选池项均不变（见 ROADMAP）。

## 3. 需求清单

### R1 · CLI wrapper 临时位置守卫

**用户目标**：从构建目录（`release/`）或开发模式启动 app 后，无论自动还是手动都不应把
`~/bin/wx-kit` wrapper 指向临时产物——临时目录被下次打包清掉后 CLI 就悬空（2026-09-04 实录）。

**方案**：

- 判定逻辑抽纯函数（放 `electron/services/cli-link.ts`，注入 execPath 与 isPackaged，可单测）：
  未打包（dev）**或** execPath 处于构建输出目录（路径含 `release` 段）→ 视为临时位置。
- 两处写入点都要守卫：
  1. `cliLink:status` 处理器里「unlinked 即自动建链」的路径；
  2. 设置页「重建命令行入口」(`cliLink:create`) 的手动路径。
- 临时位置时**一律不写 wrapper**（现状不动的 Healthy wrapper 不碰）；状态返回携带临时标记，
  设置页给出一句引导：「当前从开发/构建目录运行，请从正式安装的 wx-kit 启动后再创建命令行入口」。
- 正式安装（/Applications、brew、npm）启动时行为与现状完全一致。

### R2 · 文库筛选下拉显示公众号名称（修 M56 跳转显示裸 ID）

**用户目标**：从订阅页「文库」入口进入文库后，公众号筛选框应显示**公众号名称**，而非一串
身份 ID（现状：`?account=<fakeid>` 直塞给只认名称的下拉，Antd Select 找不到匹配项就原样显示）。

**方案**：

- `accountsOf` 从「名称数组」升级为 `{id, name}[]`：同一公众号按 `normalizeAccountKey` 归并
  （身份优先——有 `accountId` 的条目定身份；名称取该号任一条目的显示名）。
- 下拉 options 的 `value` 用身份、`label` 用名称；`onChange` 写身份。筛选（`filterByAccount`
  身份优先+名称兜底）与分组（按名称）逻辑不变。
- 旧文章兼容：缺 `accountId` 的条目以名称兼任 id——与现状下拉行为等价，纯增益。
- 公众号改名后：新条目身份匹配、旧条目名称兜底，两段历史在同一名称下显示与筛选。

### R3 · 订阅页「识别」全程有反馈（2026-09-08 安哥）

**用户目标**：粘贴文章链接点「识别」后，每个阶段都有明确反馈——识别中看得见在忙、空输入与
识别失败有明确话术、成功后知道下一步该干什么，任何情况下不出现「点了没反应」。

**现状缺口**：识别是真实网络请求（拉文章页 + cover 反查，数秒级），期间按钮无 loading、
页面无提示（盲等）；空输入点击静默 return；请求成功但 0 个候选时页面无任何变化。仅失败
路径有 message。

**方案**：

- 识别中：按钮进入 loading 态并禁点，输入框同时禁用（防重复提交）——与「检查全部」按钮的
  既有 loading 模式一致。
- 空输入点击：warning 提示「先粘贴该公众号任意一篇文章的链接」，不发请求。
- 识别成功但 0 个候选：warning 提示「未识别出公众号，请确认链接是公众号文章」（这是真实可达
  路径：链接非公众号文章/文章已删）。
- 识别成功：候选列表照旧出现在输入框下方（现状保留），不加多余弹窗。
- 识别失败：保留现有 `message.error` 与登录态过期 Alert 路径，不改话术。

## 4. 交互约定

- 设置页 CLI 区在临时位置时：不弹成功提示；给一条 warning 级引导（说清「为什么现在不能建」
  和「该怎么办」），不指责用户操作。
- 文库下拉在任何入口（跳转/手动）下，显示的永远是名称；只有该号一篇都没有时才会显示
  M56 的专属空态。

## 5. 非目标

- 不做阅读数等计数展示（spike 已证伪，见 §2）。
- 不做公式保真、音视频卡片/合集/整本导出等其他内容保真（各自单独立项）。
- 不改 Windows CLI stdout（候选池原样）。
- 不动 wrapper 在临时位置之外的行为（含 conflict 不自动重写的既有判定）。

## 6. 验收清单（逐条）

- [ ] dev（未打包）启动：`cliLink:status` 不自动写 wrapper；设置页「重建」不执行并显示引导话术。
- [ ] 从 `release/` 构建产物启动：同上两条拒绝路径，且已存在的健康 wrapper 不被改动。
- [ ] 正式安装形态（打包后 .app 或 e2e 等价模拟）启动：自动建链、手动重建行为与现状一致。
- [ ] 纯函数 `isTransientExecPath` 单测覆盖：dev、release/ 目录（mac/win 形态）、正式路径三类。
- [ ] 从订阅页「文库」跳转进文库：筛选框输入框显示公众号名称，不再出现裸 ID。
- [ ] 下拉手动选择任一公众号：列表正确按该号筛选（身份匹配），清除筛选回全部。
- [ ] 混合库（新条目带 accountId + 旧条目缺 accountId）下：同一公众号在旧条目上的名称筛选仍命中。
- [ ] 订阅页识别：请求期间按钮 loading 且不可重复点击，输入框同步禁用，结束后恢复。
- [ ] 空输入点「识别」：出现引导话术，不发网络请求。
- [ ] 识别成功但 0 个候选：出现「未识别出公众号」话术，页面不表现为无反应。
- [ ] 识别成功有候选：候选列表照旧展示并可一键订阅（现状回归）。
- [ ] `npm test`、`npm run lint`、`npx tsc --noEmit -p tsconfig.json`、当前有效 GUI e2e 全绿；
      新增行为有对应单测/e2e 断言钉住。
