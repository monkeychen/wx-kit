# wx-kit v0.10.2 产品需求文档（迭代 PRD）

> R1–R2 对应 M56（2026-09-04 确认）；R3 为 v0.10.1 验收遗留补齐。当前进度见 `ROADMAP.md`，验收以本文第 6 节为准。

## 1. 一句话定义

**自动下载了什么、成没成功，要看得见；每个订阅号要能一键进入文库看它的文章。**

v0.10.1 的订阅链路（cover 最新一篇增量 + 批量下载 + 本地日报）已可靠，但定时自动下载对用户完全
不可见——它每天发生了什么没有留下任何可查的记录。本版不改变订阅的能力边界与调度语义，只把
「已经发生的事」持久地告诉用户，并打通订阅页到文库的最后一跳。

## 2. 已确认事实与根因

### 2.1 自动下载的结果没有持久记录

- 检查记录落盘结构 `CheckLogEntry`（`src/core/subscriptions.ts:25`）只记 `newFound`（发现几篇）、
  `failed` 与逐号检查失败明细，**不记 `downloaded`（实际下载几篇），更不记下了哪几篇**。
- 手动检查时的逐号结果 `RunCheckResult.perAccount[]`（含 `downloaded`）只活在当次会话内存；
  手动「下载全部待处理」的逐篇结果同样只在当次 UI 反馈，结束后无处可查。
- 结果：定时自动检查 + 自动下载完成后，订阅页只能看到「某时刻检查过、发现 N 篇」。下载了什么、
  「文库已有」和「刚下载」各占几个、有没有失败，用户只能自己跑去文库翻，感知断层。

### 2.2 订阅页到文库没有直达路径

订阅页能看出「这个号有新文章」，但要看「这个号已经攒下了哪些文章」必须切到文库页自己找筛选。
文库页 M9 起就有按公众号筛选能力，缺的只是入口与预置筛选条件的衔接。

### 2.3 匹配键可行（已核实）

文库文章 `ArticleMeta.accountId` 在下载时即归一为 `MP_WXS_<数字>`（`src/core/download-article.ts:117`），
订阅行身份经 `normalizeAccountKey` 同源归一——按身份筛选可行；旧库条目缺 `accountId` 时按公众号
名称兜底（与订阅列表既有兼容策略一致）。

## 3. 需求清单

### R1 · 自动下载结果可感知

**用户目标**：开启自动下载后，每天它替我下载了什么、成功没有，在订阅页就能看到；重启应用后
历史记录仍在；agent 通过 CLI 也能查到同样的信息。

**方案**：

- `CheckLogEntry` 扩展（全部新字段可选，旧数据零迁移）：
  - `kind?: 'check' | 'download'`（缺省 `'check'`）——一次「检查（发现）+下载（交付）」是一条
    `check` 记录；手动「下载全部待处理」这类只有交付的动作用 `download` 记录。
  - 下载汇总与逐号逐篇明细：每篇含标题与结果状态 `downloaded`（刚下载）/ `exists`（文库已有）/
    `failed`（真故障）/ `unavailable`（读者不可见）。
  - **「文库已有」不伪装成「刚下载」**，两者分开计数（延续 v0.10.1 的话术原则）。
- 落盘时机：自动检查 + 自动下载在「下载完成后」一次性写入完整记录；手动批量下载同样落记录
  （trigger 沿用 `'manual'`，kind 为 `'download'`）。检查记录容量策略（keep 50）不变。
- 订阅页展示两层：
  - 每号行内显示该号最近一次结果摘要（检查发现几篇、刚下载几篇/文库已有几篇、时间与触发方式）；
  - 检查记录弹窗每条记录可展开看逐号逐篇明细（标题 + 状态），真实故障仍保留在待处理可重试。
- CLI 两条路径（写计划时核实：M34 的「results」是 `check-now` 输出里的逐号字段，并无独立子命令；
  定时自动下载发生在 GUI 进程内，agent 当前**没有任何路径**查「自动下载了什么」）：
  - `subscription check-now` 输出的逐号 `results[]` 扩展逐篇明细；
  - `subscription list` 输出新增 `recentLog`（最近检查/下载记录，含下载明细）——这是 agent 查
    自动下载历史与 GUI 检查记录弹窗同源的入口。
  - `agent/wx-kit-skill` 同批刷新（工作流第 7 条）。

**不改变**：调度与水位语义、检查触发方式、串行与请求保护间隔、keep 50 容量——本版只加可观测。

### R2 · 订阅页每号 → 文库入口（2026-09-04 安哥）

**用户目标**：在订阅页就能跳进文库看这个号已下载的文章，不用自己去找筛选。

**方案**：

- 订阅页每个公众号行内增加「查看文库」入口，点击切换到文库页，并**按该号筛选态**呈现
  （不是滚动定位到分组），提供一键清除筛选回全部。
- 匹配键：归一后的 `accountId`（`MP_WXS_` 形态）为主，旧条目按公众号名称兜底；
  base64 fakeid 与 `MP_WXS_` 两种历史形态经归一后等价。
- 该号文库为空时，文库页呈现空筛选态与提示（「该公众号还没有已下载的文章」），不弹错误。

### R3 · v0.10.1 验收遗留补齐

- 真实文章 URL 下载与真实 `cover` 增量检查各跑一轮完整验收。
- `docs/PRD-v0.10.1.md` §6 三条未勾项逐条补勾（首检一次、防重复入待处理、全链路验证行）。

## 4. 交互约定

- 行内摘要必须能区分「发现」与「交付」：`发现 2 篇，已下载 2 篇`与`发现 2 篇，1 篇文库已有`是两种结果。
- 检查记录弹窗中：`check` 记录展示发现 + 下载明细；`download` 记录只展示交付明细并标注「补下载」。
- 批量下载进行中：沿用 M54 的总计进度与阶段反馈，不在本版重复设计。
- 文库入口跳转后处于筛选态，清除筛选的动作在文库页就地可见（沿用既有筛选控件样式）。
- 话术区分四种下载结果：刚下载 / 文库已有 / 失败（可重试）/ 不可访问（重试无用）。

## 5. 非目标

- 不改 Windows CLI stdout（连同真机验收推迟，见 ROADMAP 候选池）。
- 不做公式等保真增强（推迟到下一版，需先 spike 真实样本）。
- 不恢复列表接口 / `crawl` / 按号批量下载（服务端按账号封禁，见 AGENTS.md，勿再凿）。
- 不改自动下载的调度、水位、串行与请求保护语义；不加账号级多选或并发。
- 不新增独立日志文件：下载明细复用 `subscriptions.json` 的 `checkLog`（keep 50 容量不变）。
- 不迁移旧 `subscriptions.json` / `library.json`；新增字段全部可选，旧数据零迁移。

## 6. 验收清单（逐条）

**R1 · 自动下载结果可感知**

- [ ] 定时自动检查 + 自动下载成功后，检查记录含下载汇总与逐号逐篇明细；重启应用（新进程读取 `subscriptions.json`）后仍可查。
- [ ] 行内单号「检查」在自动下载策略下同样落含明细的记录（`trigger:'manual'`）——三条触发路径（行内/检查全部/定时）共用同一编排，可观测性一致；行内检查过程中下载阶段进度照常可见。
- [ ] 手动「下载全部待处理」落一条 `kind:'download'` 记录，明细与自动检查触发的下载可区分。
- [ ] 「文库已有」单列计数，不并入「刚下载」；四种状态（downloaded/exists/failed/unavailable）在明细中可区分。
- [ ] 下载失败的文章保留在待处理可重试；`unavailable` 不再进入待处理（沿用 M54 语义），明细中标注。
- [ ] 订阅页每号行内显示最近一次结果摘要，能区分「发现」与「交付」及触发方式（自动/手动）。
- [ ] 检查记录弹窗每条记录可展开逐号逐篇明细；旧记录（无新字段）不报错、不显示明细区。
- [ ] `subscription check-now` 的逐号 `results[]` 含逐篇下载明细；`subscription list` 输出 `recentLog`（新进程读取，与 GUI 检查记录同源）；`agent/wx-kit-skill`（SKILL.md + references）同批刷新。
- [ ] 旧 `subscriptions.json`（无新字段）升级后功能正常，零迁移。
