# wx-kit v0.8.5 产品需求文档(迭代 PRD)

> **状态:R1 已确认,2026-07-28 安哥「直接开工」**。里程碑见 §3,逐条验收见 R1 的验收清单。
> 后续若再报需求,追加为 R2… 并另拆里程碑。

## 1. 一句话定义

**一个问题,一份清单。**

v0.8.4 给了「那天发了什么」,但答案只到链接;要真拿去用,agent 还得逐个下载,
再把「刚下的」和「本来就有的」两种形状缝成一份清单。**那道缝本该由 CLI 缝。**

## 2. 需求清单

### R1 · `digest` 加 `--download`:一条命令拿到"可直接当素材"的清单(2026-07-28 安哥)

**原始需求**:获取某一天指定公众号发布的文章**并下载下来**(已下载的不重复下),
**不改变订阅水位**,最终输出的文章信息**核心是要包含本地路径**——它是给 agent 当创作素材用的。
安哥的原话点在要害上:「你只提供链接,不就意味着 agent 还得多操作一步」。

**这确实是 v0.8.4 R2 留下的缺口。** `digest` 定成纯只读时,我把"看清单"与"取内容"切得太干净:
真实用途里这两步几乎总是连着发生,而**中间那道缝要 agent 自己缝**——它得逐个 `download`,
再把「刚下的」(下载输出里有 `dir`)和「本来就有的」(得回查文库)两种形状**合并成一份清单**。
这活儿本该由 CLI 做完。

**现状核实(2026-07-28 读代码)**:

| 事实 | 位置 |
|---|---|
| **已下载的判重会把库里的 `dir` 带出来** | `download-article.ts:48`:命中 `library.has` 时返回 `{ skipped: true, title, dir }` |
| 所以「跳过的那几篇也有本地路径」这件事**不必新做** | 同上 |
| `crawl --fakeid --from X --to X` **单个号已经满足需求的九成** | 下缺的、跳已有的、不碰订阅水位(crawl 与订阅是两套东西) |
| 但它是**单号**的 | `crawl` 取 `[name]` 或 `--fakeid`,一次一个号 |
| 且输出是**下载汇总**不是素材清单 | 有 `dir`,**没有 `contentPath`**,也不带 `itemShowType` / `warnings` |

**结论:能力基本都在,缺的是"把它们收在同一个问题下、给出同一份清单"。**

**方案(2026-07-28 安哥确认)**:

- **给 `digest` 加 `--download`,不另造命令**。理由:问题还是同一个(「那天发了什么」),
  只多一个决定(「顺手把正文取来」)。另造命令会出现两条几乎一样的命令,
  用户每次都得先想"这次该用哪个"——**那是把我们的实现细节推给用户去记**。
- **`--formats <csv>` 一并提供,缺省跟设置里的默认格式走**(安哥定)。
  ⚠️ **与 `crawl` 有意不同**:`crawl --formats` 的缺省是硬编码的 `md,html,meta`。
  digest 的缺省取 `settings.defaultFormats`——**「我平时下什么就下什么」比记住一串字面量更符合直觉**。
  这处不一致是刻意的,不要"顺手统一"成硬编码;若日后要统一,应把 `crawl` 也改成跟设置走。
- **输出:每一篇只要最终在本地,就带 `dir` + `contentPath`**,不区分「刚下的」与「本来就有的」
  ——**这正是本需求的核心**:agent 拿到清单即可读正文,不必再查一次库、不必合并两种形状。
- **`itemShowType` / `warnings` 一并带出**:选题该看的两个信号(视频/文字消息没有长正文;
  warnings 是「下到了但可能不对」的唯一提示),避免 agent 为此再跑一次 `library`。
- **不带 `--download` 时行为完全不变**:只读、不写库、不推水位。
  **下载是显式选择,不是默认副作用**——`digest` 会被用来"扫一眼那天有什么",
  那种场景下自动下载几十篇(遇到视频消息上百 MB)是灾难。
- **仍然不推进订阅水位**(即使带了 `--download`)。它不是「检查更新」,
  下载与水位无关;水位只由订阅检查推进。

**待定的次要决策(实现时按项目惯例定,安哥可推翻)**:

- 下载失败的那几篇:清单里保留该条目、`downloaded: false` 且带 `error`,**不静默丢弃**
  (与 M40 的结论一致:失败必须留痕且可重试)。
- `--no-video` 是否透传:倾向透传(批量取素材时视频常常不需要,单个上百 MB)。

**验收(草)**:

- [ ] `digest --date <d> --accounts <a,b> --download` 一次拿到那天的清单,
      **缺的已下好、已有的没重下**,每篇都带 `dir` 与 `contentPath`。
- [ ] 已下载的那几篇**不产生任何下载请求**(靠判重),但清单里的路径与新下的形状一致。
- [ ] `--formats` 缺省 = 设置里的 `defaultFormats`;显式给则按给的来。
- [ ] 不带 `--download` 时输出与行为与 v0.8.4 完全一致(纯只读)。
- [ ] **带 `--download` 也不推进订阅水位**:跑完 `subscription list` 的水位不变。
- [ ] 下载失败的条目留在清单里并带原因,不静默消失。
- [ ] 逐号进度仍走 stderr,且能看出「查列表」与「下载中」两个阶段。
- [ ] **skill 同步**(SKILL.md 速查表 + commands.md 输出契约 + recipes.md 链路范例):
      这条命令的入口就是 skill;recipes 里那条「先 digest 再逐个 download」的范例
      应改为一步到位,**旧写法要删掉而不是并列**(并列会让 agent 继续用累的那条)。

## 4. 非目标

- **不做 GUI 侧的「某天素材一键取」**。先看 agent 场景是否真被用起来。
- **不推进订阅水位**(即使带 `--download`)。下载与水位无关,水位只由订阅检查推进。
- **不做并发下载**。频控纪律不破:串行 + 随机延迟。
- **不把 `crawl` 的 `--formats` 缺省一起改成跟设置走**。那是另一处的行为变更(轻度 breaking),
  要改单独议;本次只保证 digest 自己的缺省符合直觉,并把这处不一致写进注释。
- **不在 digest 里做关键词筛选**(`--include`/`--exclude` 是 crawl 的事)。
  「某天发了什么」的结果通常只有几篇,让 agent 自己挑更直接。
