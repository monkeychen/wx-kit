改版设计说明

原则：筛选为主、搜索为辅。先让人把 90 篇收窄到十几篇，再挑；搜索只作为收尾的精确查找。

一、筛选区（弹层顶部固定）

  • 时间：近 7/30/90 天、今年、全部。默认「近 30 天」——找素材绝大多数是近期行为，默认全量等于没有默认。
  • 来源：下拉按「公众号 / 墨问作者」分组，选项后带当前时间段内篇数。复用 library-view 的等价类归并逻辑，同一号的老条目不会掉队。
  • 排序：默认「发布时间：最新在前」，可切最早在前或按来源分组。与文库页共用 sortArticles，无时间的恒排末尾。
  • 搜索：辅助位，默认只匹配标题 + 来源，placeholder 明说「可留空」。不搜正文：正文匹配看似强大，实际命中无法预期，用户更算不清漏了什么。
  • 「仅看已选」开关：随时回看已挑的稿子。

二、列表区

  • 按日期分组 + sticky 组头，滚动时始终知道自己在哪一天。
  • 每行：勾选框 · 标题 · 来源 + 时间。来源带公众号/墨问角标。
  • 渐进渲染：首屏 40 条，底部「加载更多（还有 N 篇）」，全量 90 篇不一次铺满。
  • 命中行高亮为朱砂浅底，勾选状态一眼可见。

三、选择不会因为筛选而丢失

  • 已选项跨筛选保留；底部提示「已选 5 篇（其中 2 篇不在当前条件内，已保留）」。
  • 「全选命中 / 清空命中」只作用于当前筛选结果，不会误伤筛选外的选择。
  • 上限 30 篇，触顶给提示而不是静默失败。

四、底部行动条

  • 左侧：命中 N 篇 · 已选 M 篇；右侧：取消 / 主按钮。
  • 主按钮写结果：「用这 5 篇分析」，未选时禁用并写「选择文章」——按钮直接说清会发生什么。

五、空态

  • 说明是哪个条件卡住了，并给一键「放宽到全部时间」，不留死路。
