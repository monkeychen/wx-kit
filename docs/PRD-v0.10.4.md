# wx-kit v0.10.4 产品需求文档（迭代 PRD）

> 修复版（单回归修复）。**本 PRD 为发版后补档**（2026-09-09 归档）：v0.10.4 随 v0.10.3 当日
> 热修直接发布，未按规约先行成文，此后补齐。当前进度见 `ROADMAP.md`。

## 1. 一句话定义

**按公众号筛选必须覆盖该号的全部文章，无论新旧。**

## 2. 背景

v0.10.3 R2 把文库筛选值从名称换成公众号稳定身份后，安哥实测发现：选中公众号只显示最近几篇
（猫笔刀 50 篇只剩 6 篇）。根因：筛选谓词只认「身份匹配 + 名称字面兜底」两支，而真实库里
几乎每个号都是混合形态（v0.10.1 之前的旧文章无 `accountId`）——筛选值是身份 ID 时旧文章
两支都不中，整体掉队。e2e 未拦截：fixture 全是新形态条目，没有混合形态样本。

## 3. 需求

筛选谓词与归并谓词**同源**：`AccountOption` 携带组内全部归一 key（身份 + 名称形态），
`filterByAccount` 按等价类匹配；订阅页跳转的降级选项（`fallbackAccountOption`）同样双 key。

## 4. 验收（发版时已全部验证）

- [x] 混合库（同号旧条目无 accountId + 新条目有）选中该号：新旧文章全量命中（单测）。
- [x] 改名库（同身份两代名称）选中该号：全量命中，不误伤别号（单测）。
- [x] 真实库（381 篇 / 20 号）回归：所有公众号选中后命中数 ≥ 该号全部条目数（猫笔刀 50/50、
      卡兹克 38/38）。
- [x] `npm test`、lint、tsc、GUI e2e 全绿；e2e fixture 每号独立 biz（回归根因之一是 fixture
      两号共用 biz，与身份归并语义叠加暴露）。
