## 3. 保留候选：依赖安全升级

### 3.1 为什么仍值得做

2026-07-28 的快照显示 GitHub Dependabot 有 23 条 open 告警，涉及 `axios`、`react-router`、
`brace-expansion`、`fast-uri`、`js-yaml`、`postcss`、`tar` 等依赖。该数字和具体补丁版本会变化，
所以它只能作为立项依据，**不能直接当成实施时的当前事实**。

实施前先重新读取 GitHub Dependabot 告警，逐条确认：

- 当前是否仍 open；
- 是否有同大版本内的补丁；
- 是否可达当前 Electron SPA、CLI 或构建路径；
- 是否需要 major 升级，还是应基于“不可达代码路径”写明 dismiss 理由。

### 3.2 决策原则

- 有低风险补丁版本的运行时和开发依赖优先升级；
- 不为当前产品完全不可达的代码路径盲目做 major 升级；
- dismiss 必须留下可核验理由，不用“开发依赖”三个字笼统带过；
- 国内 npm 镜像不支持完整 audit API，安全事实以 GitHub Dependabot 或显式官方 registry 的审计结果为准；
- 依赖升级的风险主要在真实打包与运行时，不以单元测试通过代替应用验收。

### 3.3 验收草案

- [ ] 实施当天重新获取 Dependabot open 告警清单并记录时间点。
- [ ] 可通过 patch/minor 修复且影响当前代码路径的告警全部关闭。
- [ ] 未升级的告警逐条写明不可达路径或升级风险，并在 GitHub 留下对应处置记录。
- [ ] `npm test`、lint、typecheck、当前 GUI e2e、build 全部通过。
- [ ] 打包后的 macOS `.app` 真实启动，并调用内层 CLI 完成一篇真实微信公众号文章 URL 下载。
- [ ] GUI 回归当前有效页面：URL 下载、文库、阅读器、设置和路由；不再验收已退场页面。
- [ ] 核对 `undici` 仍保持 external，打包主进程可正常启动。

## 4. M49 已吸收的 README 工作

M49 不再按原 R3 方案重拍“按公众号下载”和“订阅页”截图，因为这些页面已退场。处理方式改为：

- README 回到“这是什么 / 能干什么 / 怎么用”；
- 删除过时截图展示，不让无效页面继续作为产品承诺；
- 明确按 URL 下载是主功能，列出已停用 GUI 和 CLI 边界；
- CLI 清单只把有效命令作为能力说明，停用命令单独列出兼容行为；
- 项目状态只保留当前版本和 ROADMAP 指针，不再复制完整发布史；
- 修正 CLI 由 `CLI_COMMANDS` 白名单分流这一事实。

以后若当前有效 GUI 有明显改版，再重拍有效页面截图；不为保持“截图数量”而展示已退场功能。

## 5. 建议里程碑

若 M49 收尾后确认继续做 v0.8.7，建议只设一个范围清晰的里程碑：

- **M50 · 依赖安全维护与运行时回归**：刷新告警 → 分级处置 → 升级依赖 → 全量验证 → 打包应用和真实 URL 验收。

不要把已取消的订阅体验补丁塞回版本，也不要在同一里程碑顺带重构休眠私有 API 代码。

## 6. 非目标

- 不恢复按公众号搜索、批量抓取、订阅或公众号后台登录；
- 不删除 M49 明确保留的休眠实现和用户历史数据；
- 不为不可达的 RSC/服务端代码路径引入无必要的大版本迁移；
- 不新增与安全升级无关的产品功能；
- 不用 fixture 下载代替真实文章 URL 的最终回归。
